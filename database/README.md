# Рабочая БД «УниМаркет»

База работает на MySQL 8.4 (модуль Open Server Panel), InnoDB, UTF-8. Схема [schema.sql](schema.sql) применена локально и состоит из 7 таблиц, приложение использует их все. Все внешние ключи заданы с ON DELETE CASCADE: когда консоль администратора удаляет пользователя, вместе с ним исчезают его кошелёк, материалы, покупки и история. Данные сервера панель хранит в `D:\OSPanel\data`.

| Таблица | Основные данные и ключи | Связи |
|---|---|---|
| users | PK id, уникальный логин, хеш пароля, необязательные имя, фамилия, email и курс, обязательный контакт для связи (свободный текст от 5 символов, видят все) | Один аккаунт служит и покупателю, и продавцу |
| wallets | PK/FK user_id, баланс (не отрицательный) | Пользователь 1:1 кошелёк |
| materials | PK id, FK author_id, название, описание, предмет, обязательный тип (`notes` для конспекта, `solutions` для решённых задач, `cheatsheet` для шпаргалки), курс, цена, состояние | Автор 1:N материалы |
| purchases | PK id, FK buyer_id и material_id, цена при покупке, время, оценка от 1 до 5 | Покупатель и материал 1:N покупки, покупка связывает пользователей и материалы как M:N |
| files | PK id, FK material_id, закрытое имя хранения, исходное имя, формат и размер | Материал 1:N файлы |
| favorites | Составной PK/FK user_id и material_id | Пользователи M:N материалы |
| point_entries | PK id, FK user_id, ссылка на покупку либо на награждённый материал (у бонуса при регистрации ссылок нет), вид (`welcome`, `reward`, `purchase`, `sale`) и изменение баланса `delta` | Кошелёк 1:N записи истории |

Оценка хранится в покупке, но показывается как оценка продавца. Текста отзыва нет, поэтому отдельная таблица оценок не нужна. Сменить автора у опубликованного или купленного материала нельзя.

Один покупатель может приобрести конкретный материал только один раз. Несколько правил проверяет PHP (классы Market и Deals) в транзакциях, потому что внешние ключи их не обеспечивают: лимит «до десяти файлов», запрет покупать свой материал и согласованное движение баллов. Нехватку баллов ловит CHECK у кошелька, остаток не может стать отрицательным.

При регистрации начисляются 100 баллов, а в `point_entries` появляется запись вида `welcome` без ссылки на покупку и материал. За каждый бесплатный материал автор получает 25 баллов (вид `reward`), и таблица допускает только одну такую запись на материал. Покупка платного материала создаёт две записи: `purchase` покупателю (минус) и `sale` продавцу (плюс). Бесплатная покупка баллы не двигает и записей не создаёт.

## Понятные запросы

Знаки `?` это параметры PHP PDO, а не подстановка текста в SQL.

```sql
-- Данные аккаунта и остатки: поиск по первичному ключу.
SELECT u.id, u.login, u.contact, w.available
FROM users u JOIN wallets w ON w.user_id = u.id
WHERE u.id = ?;

-- Последние опубликованные материалы: индекс catalog.
SELECT id, author_id, title, price
FROM materials
WHERE status = 'published'
ORDER BY created_at DESC, id DESC
LIMIT 20;

-- Каталог с фильтром по типу, сначала дешёвые: индекс filters отбирает строки, сортирует MySQL отдельно.
SELECT id, title, subject, course, price
FROM materials
WHERE status = 'published' AND type = ?
ORDER BY price ASC, id DESC
LIMIT 20;

-- Покупки конкретного пользователя: индекс начинается с buyer_id.
SELECT p.id, m.title, p.price, p.purchased_at
FROM purchases p JOIN materials m ON m.id = p.material_id
WHERE p.buyer_id = ?
ORDER BY p.purchased_at DESC
LIMIT 20;

-- Среднее число звёзд и количество оценок аккаунта продавца.
SELECT ROUND(AVG(p.rating), 1) AS rating, COUNT(p.rating) AS ratings_count
FROM materials m JOIN purchases p ON p.material_id = m.id
WHERE m.author_id = ?;

-- Сохранить звёзды: проверяется владелец покупки; оценка ставится один раз.
UPDATE purchases SET rating = ?
WHERE id = ? AND buyer_id = ? AND rating IS NULL;

-- Добавление в избранное; повторная пара отклоняется уникальным ключом.
INSERT INTO favorites (user_id, material_id) VALUES (?, ?);

-- Удаление только своего сохранения.
DELETE FROM favorites WHERE user_id = ? AND material_id = ?;
```

Уникальный логин ускоряет вход и не допускает дубликатов. Индексы нужны каталогу и кабинету. Индекс catalog ускоряет сортировку по новизне, а filters (status, type, subject, course, price) ускоряет фильтры по типу, предмету, курсу и цене. Индекс sales обслуживает покупки материала, history историю кошелька. Скорость под нагрузкой мы не измеряли, полнотекстового поиска пока нет.

## Локальное подключение

- Адрес базы: `mysql-8.4.local` (127.0.1.31 в hosts, его прописывает панель), порт `3306`, база `unimarket`, пользователь `unimarket`.
- Пароль приложения лежит в локальном `config/local.php`, публиковать его нельзя. У этого пользователя есть только права SELECT, INSERT, UPDATE и DELETE, структуру базы он менять не может.
- Сервер базы это модуль MySQL-8.4 панели. Перед работой включи его.
- `scripts/init-db.php` подключается как `root` без пароля (так панель настроена по умолчанию, MySQL слушает только локальный адрес). Скрипт создаёт недостающие таблицы, обновляет связи до ON DELETE CASCADE и переводит базу старой схемы (с резервом баллов и статусами покупок) на текущую. При этом пользователи, кошельки, материалы, файлы и история бонусов сохраняются, а бесплатные покупки переносятся. Если в базе есть платные или незавершённые покупки старого формата, скрипт останавливается и ничего не меняет. Общей системой миграций он не является.
- Базу можно смотреть в браузере: [http://phpmyadmin.local](http://phpmyadmin.local) (phpMyAdmin из Open Server Panel). В списке «Текущий сервер» выбери `MySQL-8.4 (root)`, затем базу `unimarket`. После регистрации на сайте обнови таблицу `users`. Проект панели `D:\OSPanel\home\phpmyadmin.local` переименован из `phpmyadmin` и использует Apache и PHP-8.3.
