# Рабочая БД «УниМаркет»

MySQL Community Server 8.4.13 LTS, InnoDB, UTF-8. [schema.sql](schema.sql) применён локально; всего 7 таблиц. Регистрация и вход работают; остальные таблицы пока без пользовательских операций. Схема не означает готовую публикацию, оплату или оценку. Данные сервера хранятся в storage/mysql8.

| Таблица | Основные данные и ключи | Связи |
|---|---|---|
| users | PK id, уникальный логин (он же имя продавца), хеш пароля, необязательный курс | Аккаунт покупателя и продавца один |
| wallets | PK/FK user_id, доступный остаток и резерв | Пользователь 1:1 кошелёк |
| materials | PK id, FK author_id, описание, предмет, курс, цена, состояние | Автор 1:N материалы |
| purchases | PK id, FK buyer_id/material_id, цена при покупке, состояние и срок, проблема, факт замены, оценка 1–5 | Покупатель и материал 1:N покупки; покупка связывает пользователей и материалы M:N |
| files | PK id, FK material_id **либо** purchase_id, закрытое имя хранения, исходное имя, формат и размер | Исходные файлы 1:N к материалу; замена 1:N к покупке |
| favorites | Составной PK/FK user_id + material_id | Пользователи M:N материалы |
| point_entries | PK id, FK user_id, ссылка на покупку либо награждённый материал, вид и изменение остатков | Кошелёк 1:N записи истории |

Одна оценка хранится в каждой завершённой покупке, но показывается как оценка продавца. Текста отзыва нет; отдельная таблица оценок не нужна. Смена автора уже опубликованного/купленного материала не предусматривается.

У одного покупателя одна запись приобретения конкретного материала; повторное приобретение после возврата отдельно не реализовано. Возврат и замена пока только правила спецификации. Ограничение «до пяти исходных файлов», запрет покупки своего материала, сроки, однократная замена и согласованное движение баллов должны проверяться будущими серверными операциями в транзакциях: одни внешние ключи этого не обеспечивают.

Награда +100 остаётся открытым бизнес-вопросом. Таблица истории допускает единственную награду за материал, но автоматическое начисление пока не реализовано. При регистрации оба остатка равны нулю, запись о нулевом движении не создаётся.

## Понятные запросы

Знаки `?` — параметры PHP PDO, а не подстановка текста в SQL.

```sql
-- Данные аккаунта и остатки: поиск по первичному ключу.
SELECT u.id, u.login, w.available, w.reserved
FROM users u JOIN wallets w ON w.user_id = u.id
WHERE u.id = ?;

-- Последние опубликованные материалы: индекс catalog.
SELECT id, author_id, title, price
FROM materials
WHERE status = 'published'
ORDER BY created_at DESC, id DESC
LIMIT 20;

-- Покупки конкретного пользователя: индекс начинается с buyer_id.
SELECT p.id, m.title, p.price, p.status, p.purchased_at
FROM purchases p JOIN materials m ON m.id = p.material_id
WHERE p.buyer_id = ?
ORDER BY p.purchased_at DESC
LIMIT 20;

-- Среднее число звёзд и количество оценок аккаунта продавца.
SELECT ROUND(AVG(p.rating), 1) AS rating, COUNT(p.rating) AS ratings_count
FROM materials m JOIN purchases p ON p.material_id = m.id
WHERE m.author_id = ? AND p.status = 'completed';

-- Сохранить звёзды: проверяются владелец покупки и её завершение.
UPDATE purchases SET rating = ?
WHERE id = ? AND buyer_id = ? AND status = 'completed' AND rating IS NULL;

-- Добавление в избранное; повторная пара отклоняется уникальным ключом.
INSERT INTO favorites (user_id, material_id) VALUES (?, ?);

-- Удаление только своего сохранения.
DELETE FROM favorites WHERE user_id = ? AND material_id = ?;
```

Уникальный логин ускоряет вход и не допускает дубликаты. Индексы catalog/filters обслуживают каталог; deadlines — будущую обработку истёкших сроков; history — историю кошелька. Скорость под нагрузкой не измерялась, полнотекстовый поиск пока не реализован.

## Локальное подключение

- Адрес БД: `127.0.0.1`, порт `3306`, база `unimarket`, пользователь `unimarket`.
- Пароль приложения находится в локальном `config/local.php`; не публиковать его. Этот пользователь имеет только SELECT/INSERT/UPDATE/DELETE, не меняет структуру БД.
- Сервер и файлы БД запускаются скриптом `scripts/start.ps1`; данные — в `storage/mysql8`. Отдельная служба Windows не устанавливается. После перезагрузки ПК сначала запускать этот скрипт.
- `scripts/init-db.php` применяется под локальным администратором из `storage/mysql-admin.json`. Повторный запуск создаёт недостающие таблицы, но не является системой миграций и не изменяет уже существующие поля.
- Для просмотра используется Beekeeper Studio 6.2.0 portable из Downloads пользователя. Подключение «УниМаркет — MySQL» сохранено и проверено, таблица users открыта. В ней появляются зарегистрированные аккаунты; после регистрации нажать Refresh внизу таблицы. Данные клиента лежат в Downloads/beekeeper_studio_data, это настройки Beekeeper, а не файлы базы сайта.

Предыдущие DATABASE_CONCEPT.md и draw.io относятся к прежней версии с услугами, чатами и администратором; для текущей структуры использовать этот документ и schema.sql.
