# УниМаркет: настройка компьютера другим ИИ-агентом

Инструкция подготовлена 3 ноября 2026 года по текущим рабочим файлам проекта. Основной сценарий — Windows x64. Это задание агенту, который работает на компьютере участника команды и может выполнять команды, скачивать программы и менять локальные настройки.

## Задание агенту: начни выполнение после получения этого файла

Пользователь передаёт тебе этот Markdown-файл как самостоятельное задание. Дополнительное сообщение, отдельный промпт и повторное подтверждение начала работы не требуются. Проверь компьютер, установи недостающие инструменты и настрой доступное окружение для УниМаркета. Выполняй действия сам в пределах доступных инструментов и разрешений, а не только пересказывай инструкцию.

Сначала определи, доступны ли исходники проекта в текущей рабочей папке. Не предполагай, что файл лежит в корне репозитория: его могли прикрепить к чату отдельно. Не ищи проект по всему диску без необходимости и не придумывай адрес GitHub.

**Если передан только этот файл, всё равно начни подготовку компьютера.** Проверь Windows и архитектуру, PowerShell, PHP, Visual C++ Runtime, Git и браузер; установи недостающее, настрой PHP и проверь расширения и Argon2id. Установи Beekeeper Studio, если его нет. Для этой части достаточно сведений ниже — файлы проекта и отдельный скилл не нужны. Не требуй сначала прислать проект и не останавливай всю работу из-за его отсутствия.

Без исходников пока не создавай БД, аккаунты MySQL, конфигурацию сайта или замену проектным скриптам. MySQL для проекта устанавливается его скриптом после получения кода. Подключение Beekeeper и проверки сайта также выполняются после получения исходников. В конце подготовки перечисли выполненное и укажи, что для оставшихся шагов нужна актуальная папка проекта или ссылка на опубликованную актуальную версию. Пока изменения автора не отправлены на GitHub, старая копия репозитория может не содержать backend, SQL и скрипты. Не воссоздавай отсутствующий backend по этому документу.

Если исходники уже доступны, выполни инструкцию до конца: настрой локальную MySQL и Beekeeper, запусти сайт, проведи проверки и перезапуск. Сохраняй существующие проекты, базы и настройки. ## 1. Задача и границы

Доведи окружение до проверенного запуска, а не только составь рекомендации. Сначала проверь, что уже установлено. Совместимые инструменты используй повторно; обновляй нужные компоненты, а не весь компьютер.

Если получен только этот MD-файл, отсутствие перечисленных документов не мешает подготовке инструментов: используй существующее, меняй минимум необходимого, не добавляй зависимости на будущее, проверяй результат каждой настройки.

## 2. Что требуется

| Компонент | Для чего и как выбирать |

| PHP 8.5 x64 | Стабильный исправляющий выпуск ветки 8.5, CLI. При отдельной установке выбирай NTS ZIP; TS тоже может работать с CLI. Проверяй расширения и Argon2id |
| Microsoft Visual C++ Runtime x64 | Актуальный совместимый v14 runtime для Windows-сборок PHP/MySQL. Не нужен полный Visual Studio или компилятор |
| MySQL Community Server 8.4.13 LTS | Именно этот архив и каталог закреплены в `scripts/setup-local.ps1`. Скрипт скачает сервер сам; отдельный MySQL Installer и служба Windows не нужны |
| Браузер | Уже установленный современный Edge, Chrome или Firefox |
| Git | Для получения и обмена исходниками. Для запуска полученной папки не обязателен |
| Beekeeper Studio | Графический просмотр MySQL. Настроить после запуска БД; сайт от клиента не зависит |

Node.js, npm, Composer, Python, Apache, Nginx, XAMPP, OpenServer, Docker, MySQL Workbench и DBeaver для текущего запуска не нужны. Не устанавливай их «на всякий случай». Figma/Figwright нужны при работе над дизайном, но не для запуска существующего сайта. Редактор используй имеющийся.

## 3. Проверка исходников и компьютера

Если папка проекта доступна, определи её абсолютный путь. Путь автора `D:\GitHub PROJECTS\unimarket` не переносится на чужой компьютер. Ниже вместо примера указывай реальный путь; пробелы в нём допустимы. Если папки пока нет, пропусти `Set-Location` и проверки проектных файлов, выполни диагностику компьютера, разделы 4–5 и установку клиента из раздела 8. Разделы 6–7, подключение к БД и раздел 9 отложи до получения исходников.

```powershell
Set-Location -LiteralPath 'C:\Projects\unimarket'
$PSVersionTable.PSVersion
[System.Runtime.InteropServices.RuntimeInformation]::OSArchitecture
Get-Command pwsh, php, git, winget -ErrorAction SilentlyContinue | Select-Object Name, Source
Get-ExecutionPolicy -List
```

Убедись, что имеются `index.html`, `pages/auth/login.html`, `pages/catalog.html`, `router.php`, `backend/bootstrap.php`, `backend/AuthHandler.php`, `backend/auth.php`, `database/schema.sql`, `config/example.php`, `scripts/setup-local.ps1`, `scripts/start.ps1`, `scripts/stop.ps1`, `scripts/init-db.php`, `scripts/shutdown-db.php`, `tests/auth.php`, CSS/JS и локальные шрифты. Если ключевых файлов нет — это неполная копия, а не отсутствие установленной программы.

Если есть `.git`, выполни `git status --short` и сохрани чужие незакоммиченные изменения. Не делай `reset --hard`, `clean`, принудительное переключение ветки или замену всей папки.

Проверь порты **до** запуска setup/start/stop:

```powershell
Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
    Where-Object { $_.LocalPort -in 3306, 8000 } |
    Select-Object LocalAddress, LocalPort, OwningProcess
```

Для каждого найденного PID посмотри имя, путь и командную строку:

```powershell
# Подставь настоящий PID из предыдущей команды.
Get-CimInstance Win32_Process -Filter 'ProcessId=1234' |
    Select-Object ProcessId, Name, ExecutablePath, CommandLine
```

Если 3306 занят чужой MySQL/MariaDB, не запускай скрипты: setup считает любой слушатель на этом порту подходящим сервером и затем пытается инициализировать БД. Если 8000 занят чужим приложением, start может просто завершиться с сообщением, хотя УниМаркет не запущен. Ничего не останавливай по одному номеру порта. Сначала установи принадлежность процесса. Если это другой нужный проект, сообщи о конфликте и согласуй освобождение порта или последовательную настройку всех зависимых мест. Порт 3306 закреплён в нескольких PHP/PowerShell-файлах, 8000 также используется тестом; изменение одной команды не решает конфликт.

Если в полученной папке уже есть `storage/mysql8`, `storage/mysql-admin.json` или `config/local.php`, считай это существующим окружением. Не удаляй и не перезаписывай данные. Проверь согласованность файлов без вывода секретов; при необходимости сделай закрытую локальную резервную копию. Не копируй работающий каталог MySQL как обычную папку: для копии файлов данных сначала нужна штатная остановка, либо корректный дамп.

## 4. Установка PowerShell и базовых инструментов

При отсутствии PowerShell 7 установи стабильную версию по [официальной инструкции Microsoft](https://learn.microsoft.com/en-us/powershell/scripting/install/install-powershell-on-windows). Если доступен WinGet:

```powershell
winget install --id Microsoft.PowerShell --exact --source winget
```

Для уже установленного пакета сначала проверь версию; при необходимости используй `winget upgrade --id Microsoft.PowerShell --exact --source winget`. Preview не выбирать. После установки открой `pwsh -NoProfile` и заново проверь `$PSVersionTable.PSVersion`. Установка рядом с Windows PowerShell 5.1 нормальна; удалять 5.1 не надо.

Git, если нужен и отсутствует:

```powershell
winget install --id Git.Git --exact --source winget
```

Если WinGet отсутствует или пакет не найден, используй официальные установщики: [PowerShell](https://github.com/PowerShell/PowerShell/releases), [Git для Windows](https://git-scm.com/downloads/win). Не подбирай случайные сайты и не запускай неизвестные установочные скрипты. Инсталляторы и архивы сохраняй в Downloads пользователя; проверяй официальную контрольную сумму, если она опубликована, и цифровую подпись установщика.

Установи или обнови необходимый x64 runtime по [официальной странице Microsoft Visual C++ Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist). Если установщик сообщает о необходимой перезагрузке, сообщи об этом пользователю; не перезагружай компьютер самостоятельно.

После установки инструментов обнови PATH текущего процесса или открой новый терминал: старый процесс редактора может не увидеть изменения PATH. Не удаляй прежние записи PATH и другие установки PHP. Если нужны права администратора/UAC, используй штатный механизм; запрет инструмента или политики не обходи.

## 5. Установка и настройка PHP

Сначала выполни `Get-Command php -All`, `php -v`, `php --ini`, `php -m`. Если подходящий PHP уже есть и проверки проходят, переустановка не нужна.

Если PHP отсутствует или несовместим:

1. Возьми стабильный **PHP 8.5 x64 NTS ZIP** со [страницы загрузок PHP для Windows](https://www.php.net/downloads.php?os=windows). Сверь SHA256 архива с опубликованным значением. Номер исправляющего выпуска выбирай по официальной странице, не по выдуманной ссылке на ZIP.
2. Распакуй отдельно, например в `%LOCALAPPDATA%\Programs\PHP\8.5`. Не распаковывай поверх неизвестной установки. Сохрани весь комплект DLL и папку `ext`.
3. Для новой установки создай `php.ini` из `php.ini-development` рядом с `php.exe`. Для существующего ini сначала сделай резервную копию и меняй только нужные параметры. Не создавай второй набор повторяющихся `extension=`.
4. В `php.ini` укажи абсолютный `extension_dir` к папке `ext` выбранной установки и включи необходимые расширения.
5. Добавь папку с `php.exe` в пользовательский PATH с сохранением остальных записей. Проверь, что именно этот PHP выбирается командой `php`, в том числе в новом терминале.

Необходимая часть ini, путь здесь примерный:

```ini
; Подставить абсолютный путь к ext именно своей установки PHP.
extension_dir = "C:/Users/USER/AppData/Local/Programs/PHP/8.5/ext"
extension=pdo_mysql
extension=mbstring
extension=curl
extension=openssl
date.timezone = UTC
```

`pdo_mysql` нужен для БД, `mbstring` — для проверки длины пароля, `curl` — для существующего интеграционного теста; OpenSSL включаем для работы с TLS. PDO, session, JSON, filter и hash также должны быть доступны, обычно они уже встроены. Argon2id — возможность сборки PHP, её не исправляют строкой `extension=argon2`.

Официальная справка по установке, выбору NTS/TS и runtime: [PHP: установка готовых Windows-сборок](https://www.php.net/manual/en/install.windows.manual.php).

Выполни проверки в PowerShell 7:

```powershell
php -v
php --ini
php -m
php -r 'foreach (["pdo_mysql", "mbstring", "curl", "openssl", "session", "json", "filter", "hash"] as $name) { if (!extension_loaded($name)) { fwrite(STDERR, "Missing: $name\n"); exit(1); } } if (!in_array("argon2id", password_algos(), true)) { fwrite(STDERR, "Missing: argon2id\n"); exit(1); } echo "PHP OK\n";'
```

Проверяй код завершения каждой команды (`$LASTEXITCODE`), а не только наличие текста. Ожидаются PHP 8.5, правильный путь ini, `PHP OK`, отсутствие startup warning и код 0. Ошибки загрузки DLL сначала исправь; запуск сайта не заменяет эту проверку.

## 6. Разрешение запуска локальных скриптов

Используй PowerShell 7 и запускай команды из корня проекта. Если скрипт блокируется как скачанный из интернета, сначала прочитай его и затем разблокируй только проверенные файлы:

```powershell
Unblock-File -LiteralPath '.\scripts\setup-local.ps1'
Unblock-File -LiteralPath '.\scripts\start.ps1'
Unblock-File -LiteralPath '.\scripts\stop.ps1'
```

Если локальная политика всё ещё запрещает скрипты, при отсутствии организационного запрета можно задать разрешение только для текущего процесса:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Не устанавливай глобальный Bypass/Unrestricted и не меняй MachinePolicy/UserPolicy. Организационный запрет требует участия администратора организации.

## 7. Создание MySQL и первый запуск

Ещё раз убедись, что 3306/8000 свободны либо принадлежат этой конкретной копии УниМаркета. Не устанавливай параллельно службу MySQL через MSI и не заменяй выбранный MySQL на MariaDB.

Из корня проекта в PowerShell 7:

```powershell
.\scripts\start.ps1
```

Отдельно запускать setup перед start не требуется: `start.ps1` уже вызывает его. После обновления PATH убедись, что терминал видит правильный `php.exe`.

Что делают существующие скрипты:

- Проверяют доступность `php` и создают локальные рабочие каталоги.
- При отсутствии скачивают MySQL **8.4.13 winx64** в `%LOCALAPPDATA%\UniMarket\runtime\mysql-8.4.13-winx64` и сверяют закреплённую MD5. Это текущая проверка скрипта, не SHA256 и не цифровая подпись. Если есть официальная более сильная проверка, дополнительно выполни её.
- Создают данные сервера в `storage/mysql8`, генерируют собственный пароль администратора в `storage/mysql-admin.json`. Временный `storage/mysql-init.sql` удаляется после успешной инициализации.
- Запускают MySQL на `127.0.0.1:3306` без службы Windows.
- Через `scripts/init-db.php` создают БД `unimarket`, семь таблиц, отдельного пользователя приложения с правами SELECT/INSERT/UPDATE/DELETE и локальный `config/local.php` со сгенерированным паролем.
- Запускают PHP на `127.0.0.1:8000` с `router.php`, сохраняют PID и журналы в `storage/`.

Не создавай заранее `config/local.php` простым копированием примера с паролем-заглушкой. В чистой копии этот файл создаётся автоматически. Не применяй SQL вручную второй раз после успешного старта.

Версия MySQL и URL архива зафиксированы в скриптах. Если официальный архив недоступен или контрольная сумма отличается, не отключай проверку и не подставляй новый номер только в URL. Проверь [официальные архивы MySQL](https://downloads.mysql.com/archives/community/) и текущие скрипты; согласованное обновление должно учитывать каталог runtime, ссылку, контрольную сумму и совместимость теста. Для обычной подготовки воспроизводи закреплённую версию. Справка: [MySQL 8.4 для Windows](https://dev.mysql.com/doc/refman/8.4/en/windows-installation.html).

Убедись, что процессы действительно запущены из нужных путей. Сообщение `UniMarket: ...` само по себе не доказывает работоспособность сервера. Открой [локальный сайт](http://127.0.0.1:8000). Всегда используй один адрес `127.0.0.1`, чтобы не путать cookie с `localhost`.

Нельзя запускать только Live Server, открывать `index.html` через `file://` или выполнять `php -S` без router: так регистрация и ограничения доступа не будут работать как предусмотрено. Встроенный PHP-сервер предназначен для локальной разработки, это не инструкция хостинга.

## 8. Настройка Beekeeper Studio

Если подходящий клиент уже установлен, используй его. Иначе скачай бесплатную Community-версию для Windows x64 с [официального сайта](https://www.beekeeperstudio.io/get) или [официальных релизов](https://github.com/beekeeper-studio/beekeeper-studio/releases). У автора проверялась portable-версия 6.2.0; клиенту не обязательно иметь именно этот выпуск. Выбирай стабильный поддерживаемый вариант, проверяй опубликованную контрольную сумму. Сохрани скачанный файл в Downloads. Платная подписка и облачная синхронизация для локальной БД не нужны. Установить и проверить открытие клиента можно до получения проекта; подключение ниже создавай только после запуска проектной MySQL и появления локальных реквизитов.

После запуска MySQL создай подключение:

| Поле | Значение |
|---|---|
| Название | УниМаркет — MySQL |
| Тип | MySQL |
| Host | `127.0.0.1` |
| Port | `3306` |
| Database | `unimarket` |
| User | `unimarket` |
| Password | Локальное значение из `config/local.php` на этом компьютере |
| SSH tunnel | Выключен |
| SSL | Не требуется для этого локального сервера |

Бери пароль локально и вводи непосредственно в клиент. Не выводи содержимое config в чат, отчёты, скриншоты или Git. Для обычного просмотра не используй root. Пароль root из `storage/mysql-admin.json` отличается от пароля приложения.

Нажми проверку подключения, сохрани его локально, открой `users`. Должны быть видны семь таблиц: `users`, `wallets`, `materials`, `purchases`, `files`, `favorites`, `point_entries`. Новая БД может быть пустой. Настройки portable-клиента не являются файлами сервера MySQL и не должны передаваться другим участникам.

Если у агента нет управления интерфейсом клиента, самостоятельно выполни доступные CLI-проверки и подготовь точные поля подключения. В итоговом отчёте честно укажи, что проверка GUI не выполнена; не выдавай скачанный установщик за настроенное подключение.

## 9. Обязательные проверки

### Синтаксис PHP

```powershell
$phpFiles = Get-ChildItem -LiteralPath backend, scripts, tests, config -Filter '*.php' -File -Recurse
$phpFiles += Get-Item -LiteralPath '.\router.php'
foreach ($phpFile in $phpFiles) {
    php -l $phpFile.FullName
    if ($LASTEXITCODE -ne 0) { throw "Ошибка синтаксиса: $($phpFile.FullName)" }
}
```

### Проверка backend и БД

При работающих серверах выполни:

```powershell
php .\tests\auth.php
if ($LASTEXITCODE -ne 0) { throw 'Проверка доступа не пройдена' }
```

Тест выполняй на локальном окружении разработки без параллельных проверок входа. Он временно меняет локальный лимит попыток, создаёт собственный случайный тестовый аккаунт и удаляет его при штатном завершении через finally; прежний лимит восстанавливается. При аварийном прерывании проверь возможный остаток тестовых данных, не очищай всю таблицу users.

Ожидается строка `OK: ...` и код 0. Проверяются регистрация, нулевой кошелёк, хеш пароля, повторный email, вход/выход, CSRF, закрытые пути, лимит, семь таблиц и ограничение отрицательного баланса. Это не проверка будущих покупок и публикации. Тест ожидает MySQL-код CHECK 3819; подмена сервера на MariaDB может дать другой результат.

### Проверка в браузере

1. В гостевой сессии открой главную. Проверь загрузку CSS, иконок и шрифта.
2. Перейди к регистрации, введи отдельный проверочный email и пароль от восьми символов. Запомни данные локально, не публикуй пароль.
3. Убедись, что сразу открылся каталог, виден введённый email, доступно 0 и зарезервировано 0 баллов.
4. Обнови страницу: вход должен сохраниться.
5. Выйди, открой `/pages/catalog.html`: должно перенаправить на форму входа.
6. Проверь отказ при неправильном пароле, затем успешный вход и выход.
7. В Beekeeper обнови users и wallets: созданный вручную аккаунт и нулевой кошелёк видны. Этот аккаунт остаётся до отдельного удаления, в отличие от аккаунта автоматического теста.
8. Проверь консоль браузера и сеть: нет ошибок JS, необъяснённых ответов 500 и пропавших основных ресурсов. Проверять можно вручную в имеющемся браузере; установка Node.js/Playwright не обязательна.

Отсутствующая страница помощи или ещё не реализованная покупка не являются ошибками установки. Не дописывай эти функции в рамках настройки.

### Остановка и повторный запуск

После подтверждения принадлежности серверов этой папке:

```powershell
.\scripts\stop.ps1
.\scripts\start.ps1
php .\tests\auth.php
if ($LASTEXITCODE -ne 0) { throw 'Проверка после перезапуска не пройдена' }
```

Проверь сохранность вручную созданного аккаунта после перезапуска. Не проверяй её очисткой/пересозданием БД. После успешной настройки оставь сайт запущенным, если пользователь не попросил иное.

## 10. Частые проблемы

| Признак | Что проверить и исправить |
|---|---|
| `pwsh` или `php` не найден | Установка, пользовательский PATH, новый терминал, `Get-Command ... -All` |
| Ошибка `ToHexString` или `RandomNumberGenerator.Fill` | Запуск скрипта в старом Windows PowerShell; перейти в PowerShell 7 |
| `VCRUNTIME...dll`, `MSVCP...dll` отсутствует | Официальный совместимый Microsoft Visual C++ Runtime x64; не скачивать отдельные DLL |
| `Unable to load dynamic library` | Путь `extension_dir`, наличие ext и зависимых DLL, совпадение x64 и сборки; не смешивать DLL разных версий PHP |
| `could not find driver` | `pdo_mysql` в загруженном ini, затем перезапустить PHP-сервер |
| `undefined function mb_strlen/curl_init` | `mbstring`/`curl`, правильный ini, перезапуск PHP |
| Недоступен Argon2id | Нужна сборка PHP с поддержкой алгоритма; не ослаблять хранение паролей ради обхода |
| `Connection refused`, ответ 503 | Процесс MySQL, порт, `storage/mysql8/server.log`, затем `storage/php-error.log` |
| `Access denied` | Принадлежность сервера и согласованность локальных реквизитов; не сбрасывать root и не удалять данные наугад |
| Каталог данных существует без реквизитов | Защита setup от перезаписи; восстановить согласованный комплект из закрытой копии или согласовать отдельное чистое окружение |
| Порт занят | Определить владельца; не делать `taskkill`/`Stop-Process` по всем PHP/MySQL и не вызывать stop для чужого сервера |
| HTTP 429 при входе | Локальный лимит 20 попыток за 15 минут; дождаться срока, не удалять все сессии и лимиты |
| Схема не обновилась после получения нового кода | init-db создаёт отсутствующие таблицы, но не является системой миграций; существующие поля автоматически не обновляются |
| Окна серверов не видны | Они запускаются скрыто; проверить процесс, порты и журналы |
| После перезагрузки сайт недоступен | Автозапуск и служба не настроены; снова выполнить start |

Для диагностики читай только нужные журналы, скрывай пароли, cookie и персональные данные. Пустой или отсутствующий журнал не заменяет проверку процесса и HTTP. При неудачной загрузке не отключай TLS, антивирус или проверку контрольных сумм.
