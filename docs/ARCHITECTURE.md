# Структура «УниМаркета»

Актуальное решение согласовано 22 октября 2026: одна самостоятельная HTML-страница на файл, CSS и JavaScript отдельно, без сборки HTML. Прежняя схема src/pages + partials + public отменена.

Backend: router.php → backend/api/*.php → классы (AuthHandler, Market, Deals, FileStore, Points) и PDO → MySQL 8.4. Текущая схема на 7 таблиц — database/schema.sql; описание и DML — database/README.md. Требования — только docs/mvp/SPECIFICATION.md.

## Структура

```text
unimarket/
├── index.html                 # весь лендинг: шапка, секции, подвал
├── pages/
│   ├── auth/                  # login.html, register.html (два шага), recovery.html
│   ├── catalog.html           # каталог: поиск, фильтры, сортировка
│   ├── material.html          # страница материала и покупка
│   ├── publish.html           # публикация
│   ├── favorites.html, author.html
│   └── account.html, purchases.html, sales.html, settings.html   # кабинет
├── assets/
│   ├── css/                   # base (общее), forms, cards, app (после входа), catalog, landing, auth
│   ├── js/                    # common (запросы, шапка), forms (проверка форм, окна), cards (карточки),
│   │                          # по файлу на страницу: login, register, catalog, material, publish и т. д.
│   ├── icons/                 # SVG из Figma
│   └── fonts/                 # Rubik, Onest (400/500/600), Golos Text с лицензиями OFL
├── backend/
│   ├── bootstrap.php          # PDO, сессия, runApi(), защита POST, лимит попыток
│   ├── validation.php         # правила логина, пароля, профиля
│   ├── api/                   # auth, market, deals, account, download — по одному файлу на адрес /api/<имя>
│   └── AuthHandler, Market, Deals, FileStore, Points   # логика и SQL
├── config/local.php           # пароль БД; создаёт scripts/init-db.php, не в Git
├── database/                  # schema.sql и README.md
├── scripts/                   # init-db.php, seed.php (тестовые данные), admin.php (консоль)
├── storage/                   # сессии, лимиты и загруженные файлы, не в Git
├── docs/
├── router.php                 # белый список страниц и API
├── .htaccess                  # Apache: assets напрямую, остальное в router.php
├── НАСТРОЙКА-ПРОЕКТА.md
└── README.md
```

Новые разделы добавляем по задачам, без пустых заготовок. Файлы API лежат в backend/api/, а классы в backend/: на Windows `Market.php` и `market.php` — один файл, поэтому имена не должны различаться только регистром.

## HTML и просмотр

Весь лендинг редактируем в корневом index.html. Новую страницу создаём целиком в pages/ соответствующего раздела. У каждой страницы свои head, header и main, footer — только там, где он есть в макете; HTML-вставок и сгенерированных копий нет.

Запуск — Open Server Panel 6: модули Apache, PHP-8.3 и MySQL-8.4, проект unimarket.local (http://unimarket.local). Папка проекта в панели — ссылка на репозиторий, потому что панель не принимает пробелы в пути. Первичная подготовка — php scripts/init-db.php. Открытие HTML напрямую или через Live Server не выполняет сессии и API. Node.js не является зависимостью приложения; сборка не нужна.

Пути считаем относительно конкретного HTML-файла. В index.html иконка подключается как assets/icons/имя.svg, страница входа — pages/auth/login.html. В pages/auth/login.html путь к общей иконке начинается с ../../assets/, к лендингу — ../../index.html. Не переносить одинаковый относительный путь на другую глубину без проверки.

## Стили и JavaScript

Сначала подключаем assets/css/base.css, затем CSS текущей страницы. В base лежат шрифт, смысловые переменные, базовые правила, контейнер, кнопки и подвал; forms.css — поля форм; cards.css — карточка материала; app.css — страницы после входа (шапка, панели, списки, окна). В landing.css — секции лендинга и media-запросы.

JavaScript — ES-модули (`type="module"`): общее лежит в common.js, forms.js и cards.js, у каждой страницы свой короткий файл. Шапка, подвал и меню кабинета рисуются из common.js, поэтому повторяющегося HTML на страницах нет. Данные из API всегда вставляются как текст (функция `el`), а не как HTML.

Лендинг работает без JavaScript: две ссылки аккаунта всегда видны в одном nav. Раскладок три: ноутбук (от 1200px), планшет (768–1199.98px), телефон (до 767.98px). На телефоне CSS показывает иконки входа и регистрации вместо текста; доступные названия сохраняются через aria-label. Кнопка регистрации в приветствии на телефоне имеет ширину плашки баллов. Карточки на телефоне используют Flexbox в одну колонку. Их мобильная min-height обнулена, поэтому высоту определяет содержимое.

## Принципы

- KISS и DRY, короткий читаемый код.
- Жёсткого предела строк нет. 300–400 строк понятного HTML одной страницы допустимы.
- Не склеивать операции и не минифицировать исходники ради краткости.
- Разделять файлы по ответственности и удобству, не ради счётчика.
- Небольшое повторение шапки/подвала между HTML-страницами допустимо на текущем этапе.
- Комментарии писать на русском, пояснять причину, а не пересказывать очевидное.
- Сохранять семантику, клавиатуру, видимый фокус и обработку ошибок.
- Главная: Grid на компьютере/планшете, Flexbox через media-запросы на телефоне.
- Корзины нет: материал приобретается со страницы описания.

## Backend

bootstrap.php отвечает за PDO, сессии, ответы и защиту POST (токен CSRF). Каждый файл в backend/api/ — один адрес /api/<имя>; все они запускаются через runApi(), которая превращает ошибки в JSON. ApiError — ошибка для пользователя со своим HTTP-кодом. Market — публикация, каталог, страница материала, избранное; Deals — покупка, резерв, подтверждение, обращение, замена, возврат, оценка и автоматические сроки; Points — единственное место, где меняются баллы (кошелёк и запись истории вместе, в транзакции); FileStore — проверка и хранение файлов.

Планировщика нет: покупки с истёкшим сроком закрываются при первом обращении любого пользователя (`Deals::settleOverdue()` из `currentUser()`).

Закрытые файлы лежат в storage/files под случайными именами без расширения; скачивает их только /api/download после проверки прав, с типом application/octet-stream и заголовком attachment.

.htaccess отдаёт напрямую только ресурсы assets, остальные запросы идут в router.php: он разрешает известные страницы и API, а config, backend, scripts, database и storage закрыты ответом 404. Страницы после входа доступны только вошедшим, лендинг и формы — только гостям. config/local.php и storage игнорируются Git. При размещении нужен Apache с mod_rewrite и AllowOverride, иначе .htaccess не сработает и закрытые папки откроются.

Приложение подключается к БД пользователем только с правами на данные (SELECT, INSERT, UPDATE, DELETE). Схема применяется CLI-скриптом init-db.php.

## Ветки и порядок работы

- `mvp` — рабочая ветка. Этапы 3–9 из спецификации пишутся здесь; после каждого завершённого этапа ставится аннотированный тег `mvp-etap-N` (`git tag -a mvp-etap-3 -m "Этап 3: публикация"`).
- Участники работают в своих ветках от `mvp` и вносят изменения через pull request в `mvp`. Прямые коммиты в `mvp` делает только владелец.
- `full` — полный первоначальный замысел и всё остальное. Обновляется только слиянием `mvp` → `full`: никогда не `full` → `mvp` и без rebase. Нужный файл из `full` переносится в `mvp` командой `git checkout full -- путь` отдельным коммитом.
- `main` — отдельная ветка для будущего pull request, сейчас только начальный коммит.
