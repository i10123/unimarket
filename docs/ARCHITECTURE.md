# Структура «УниМаркета»

Актуальное решение согласовано 22 октября 2026: одна самостоятельная HTML-страница на файл, CSS и JavaScript отдельно, без сборки HTML. Прежняя схема src/pages + partials + public отменена.

## Структура

```text
unimarket/
├── index.html                 # весь лендинг: шапка, секции, подвал
├── pages/                     # создаём по мере реализации
│   ├── auth/login.html        # вход, регистрация и восстановление в одном файле
│   ├── catalog/               # материалы, услуги, заявки
│   ├── account/               # разделы личного кабинета
│   ├── publish/               # размещение материала или услуги
│   ├── requests/              # создание, редактирование, описание заявки
│   ├── chats/                 # список диалогов и переписка
│   ├── admin/                 # проверка материалов
│   ├── material.html
│   ├── service.html
│   ├── author.html
│   ├── favorites.html
│   ├── help.html
│   └── 404.html
├── assets/
│   ├── css/
│   │   ├── base.css           # шрифт, переменные, базовые стили, контейнер
│   │   └── landing.css        # оформление и адаптация лендинга
│   ├── js/                    # поведение, когда оно потребуется
│   ├── icons/                 # SVG из Figma
│   ├── fonts/                 # файлы Manrope
│   └── images/                # изображения при необходимости
├── docs/
│   ├── ARCHITECTURE.md
│   └── learning/              # профиль, прогресс, карта, справочники
├── .agents/skills/ponytail/
├── AGENTS.md
├── .gitignore
└── README.md
```

Сейчас существуют index.html, pages/auth/login.html и assets/css, assets/js, assets/fonts, assets/icons. Остальные разделы добавляем по задачам, без пустых заготовок.

## HTML и просмотр

Весь лендинг редактируем в корневом index.html. Новую страницу создаём целиком в pages/ соответствующего раздела. У каждой страницы свои head, header, main и footer; HTML-вставок и сгенерированных копий нет.

Для текущего HTML достаточно открыть index.html в браузере. Локальный HTTP-сервер также подходит для разработки и потребуется для последующих обращений к API. Node.js не является зависимостью приложения; сборка не нужна.

Пути считаем относительно конкретного HTML-файла. В index.html иконка подключается как assets/icons/имя.svg, страница входа — pages/auth/login.html. В pages/auth/login.html путь к общей иконке начинается с ../../assets/, к лендингу — ../../index.html. Не переносить одинаковый относительный путь на другую глубину без проверки.

## Стили и JavaScript

Сначала подключаем assets/css/base.css, затем CSS текущей страницы. В base лежат шрифт, смысловые переменные, базовые правила и контейнер. В landing.css — секции лендинга и media-запросы. Правила компонента и его адаптации находятся рядом.

При появлении повторяемых элементов можно выделить общий CSS компонента. Не дробить правила только из-за количества строк. Обычный CSS достаточен; SCSS не обязателен.

JavaScript добавляем только для нужного поведения и подключаем отдельным файлом. Для простого действия используем функцию; класс нужен для связанных операций с собственным состоянием. FAQ уже работает через details/summary без JS.

Лендинг работает без JavaScript: две ссылки аккаунта всегда видны в одном nav. До 600px CSS показывает иконки входа и регистрации вместо текста; доступные названия сохраняются через aria-label. Кнопка регистрации в приветствии до 600px имеет ширину плашки баллов. Карточки на телефоне используют Flexbox: одна колонка до 600px, две с переносом на 600–767px. Их мобильная min-height обнулена, поэтому высоту определяет содержимое.

## Принципы

- Обязателен ponytail в режиме full; KISS и DRY, короткий читаемый код.
- Жёсткого предела строк нет. 300–400 строк понятного HTML одной страницы допустимы.
- Не склеивать операции и не минифицировать исходники ради краткости.
- Разделять файлы по ответственности и удобству, не ради счётчика.
- Небольшое повторение шапки/подвала между HTML-страницами допустимо на текущем этапе.
- Комментарии писать на русском, пояснять причину, а не пересказывать очевидное.
- Сохранять семантику, клавиатуру, видимый фокус и обработку ошибок.
- Главная: Grid на компьютере/планшете, Flexbox через media-запросы на телефоне.
- Корзины нет: материал приобретается со страницы описания.

## Будущий backend

PHP и MySQL/MariaDB подключаются отдельным этапом. При этом можно вынести общие шапку/подвал в PHP-шаблоны. Контроллеры, операции и SQL разделять, когда появится соответствующая логика; классы и интерфейсы заранее не создавать.

Серверный код, секреты и платные файлы не должны отдаваться статическим сервером. Их размещение, точку API и ограничения доступа определим вместе с backend-реализацией. Текущий HTML-предпросмотр не является конфигурацией для публикации backend.

## Текущее состояние

Лендинг в index.html подключает base.css и landing.css. Формы доступа в pages/auth/login.html используют base.css, auth.css и auth.js; регистрация открывается по #registraciya, восстановление — по #vosstanovlenie. auth.js в head без defer выбирает data-ekran до отрисовки; обработчики полей устанавливаются после DOMContentLoaded. CSS показывает только выбранную форму. JS также показывает пароль и проверяет поля, не отправляя данные. Manrope хранится локально с лицензией OFL. Адаптация разработана независимо от мобильных макетов Figma. Backend ещё не реализован.
