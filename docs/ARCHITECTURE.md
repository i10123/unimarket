# Структура «УниМаркета»

Решение согласовано 22 октября 2026: каждая страница лежит в отдельном HTML-файле, CSS и JavaScript хранятся отдельно, HTML не собирается. Прежняя схема с `src/pages`, partials и `public` отменена.

Backend устроен так: `router.php` передаёт запрос в `backend/api/*.php`, те вызывают классы (AuthHandler, Market, Deals, FileStore, Points) и PDO, а дальше идёт MySQL 8.4. Схема из 7 таблиц лежит в `database/schema.sql`, описание и примеры запросов в `database/README.md`. Требования описаны только в `docs/mvp/SPECIFICATION.md`.

## Структура

```text
unimarket/
├── index.html                 # весь лендинг: шапка и секции
├── pages/
│   ├── auth/                  # login.html, register.html (три шага), recovery.html
│   ├── catalog.html           # каталог: поиск, фильтры, сортировка
│   ├── material.html          # страница материала и покупка
│   ├── publish.html           # публикация и редактирование (с ?id=N)
│   ├── favorites.html, author.html
│   └── account.html, purchases.html, sales.html, settings.html   # кабинет
├── assets/
│   ├── css/                   # base (общее), forms, cards, app (после входа), catalog, landing, auth
│   ├── js/                    # common (запросы, шапка), forms (проверка форм, окна), cards (карточки),
│   │                          # по файлу на страницу: login, register, catalog, material, publish и т. д.
│   ├── icons/                 # SVG из Figma
│   └── fonts/                 # Rubik, Onest (400/500/600), Golos Text с лицензиями OFL
├── backend/
│   ├── bootstrap.php          # PDO, сессия, runApi(), защита POST, лимит попыток
│   ├── validation.php         # правила логина, пароля, профиля
│   ├── api/                   # auth, market, deals, account, download: по одному файлу на адрес /api/<имя>
│   └── AuthHandler, Market, Deals, FileStore, Points   # логика и SQL
├── config/local.php           # пароль БД; создаёт scripts/init-db.php, не в Git
├── database/                  # schema.sql и README.md
├── scripts/                   # init-db.php, seed.php (тестовые данные), admin.php (консоль)
├── storage/                   # сессии, лимиты и загруженные файлы, не в Git
├── docs/
├── router.php                 # белый список страниц и API
├── .htaccess                  # Apache: assets напрямую, остальное в router.php
├── НАСТРОЙКА-ПРОЕКТА.md
└── README.md
```

Новые разделы добавляем по мере задач, пустых заготовок не создаём. Файлы API лежат в `backend/api/`, а классы в `backend/`. На Windows `Market.php` и `market.php` это один файл, поэтому имена не должны отличаться только регистром.

## HTML и просмотр

Весь лендинг редактируется в корневом `index.html`. Новую страницу создаём целиком в `pages/`, в папке нужного раздела. У каждой страницы свои `head`, `header` и `main`. Футера нет нигде: он ничего не добавлял, и мы его убрали. Вставок и сгенерированных копий HTML нет.

Сайт запускается в Open Server Panel 6 с модулями Apache, PHP-8.3 и MySQL-8.4 как проект `unimarket.local` (http://unimarket.local). Папка проекта в панели это ссылка на репозиторий, потому что панель не принимает пробелы в пути. Базу первый раз готовит `php scripts/init-db.php`. Если открыть HTML напрямую или через Live Server, сессии и API работать не будут. Node.js приложению не нужен, сборки нет.

Пути считаем от конкретного HTML-файла. В `index.html` иконка подключается как `assets/icons/имя.svg`. В `pages/auth/login.html` путь к общей иконке начинается с `../../assets/`, а к лендингу ведёт `../../index.html`. Если переносишь страницу на другую глубину, проверь все относительные пути заново.

## Стили и JavaScript

Сначала подключается `assets/css/base.css`, потом CSS самой страницы. В `base` лежат шрифт, смысловые переменные, базовые правила, контейнер и кнопки. `forms.css` отвечает за поля форм, `cards.css` за карточку материала, `app.css` за страницы после входа (шапка, панели, списки, окна). В `landing.css` собраны секции лендинга и media-запросы.

JavaScript написан ES-модулями (`type="module"`). Общий код лежит в `common.js`, `forms.js` и `cards.js`, а у каждой страницы есть свой короткий файл. Шапку и меню кабинета рисует `common.js`, поэтому повторяющегося HTML на страницах нет. Данные из API вставляются на страницу только как текст (функция `el`), никогда как HTML.

Лендинг работает без JavaScript: две ссылки аккаунта всегда видны в одном `nav`. Раскладок три: ноутбук (от 1200px), планшет (от 768px до 1199.98px) и телефон (до 767.98px). На телефоне CSS показывает иконки входа и регистрации вместо текста, а доступные названия сохраняются через `aria-label`. Кнопка регистрации в приветствии на телефоне по ширине равна плашке с баллами. Карточки на телефоне идут одной колонкой на Flexbox, их мобильная `min-height` обнулена, поэтому высоту определяет содержимое.

## Принципы

- Код пишем по принципам KISS и DRY: коротко и читаемо.
- Жёсткого предела строк нет, 300 или 400 строк понятного HTML на одной странице допустимы.
- Операции не склеиваем и исходники не минифицируем ради краткости.
- Файлы делим по назначению и удобству, а не ради счётчика.
- Небольшое повторение шапки между HTML-страницами на этом этапе допустимо.
- Комментарии пишем по-русски и объясняем в них причину, а не пересказываем очевидное.
- Сохраняем семантику, работу с клавиатуры, видимый фокус и обработку ошибок.
- Главная страница использует Grid на компьютере и планшете, на телефоне Flexbox через media-запросы.
- Корзины нет: материал покупается прямо на странице с описанием.

## Backend

`bootstrap.php` отвечает за PDO, сессии, ответы и защиту POST (токен CSRF). Каждый файл в `backend/api/` обслуживает один адрес `/api/<имя>` и запускается через `runApi()`, которая превращает ошибки в JSON. `ApiError` это ошибка для пользователя со своим HTTP-кодом. Классы делят работу так:

- Market отвечает за публикацию, каталог, страницу материала и избранное.
- Deals отвечает за покупку с мгновенной оплатой продавцу, оценку и право на скачивание.
- Points единственное место, где меняются баллы: кошелёк и запись истории обновляются вместе, в одной транзакции.
- FileStore проверяет и хранит файлы.

Закрытые файлы лежат в `storage/files` под случайными именами без расширения. Скачивает их только `/api/download` после проверки прав, с типом `application/octet-stream` и заголовком `attachment`.

`.htaccess` отдаёт напрямую только ресурсы из `assets`, остальные запросы идут в `router.php`. Он пропускает известные страницы и API, а `config`, `backend`, `scripts`, `database` и `storage` закрыты ответом 404. Страницы после входа доступны только вошедшим, лендинг и формы входа только гостям. Файлы `config/local.php` и `storage` Git игнорирует. На хостинге нужен Apache с `mod_rewrite` и `AllowOverride`: без них `.htaccess` не сработает и закрытые папки откроются.

Приложение подключается к базе пользователем, у которого есть права только на данные (SELECT, INSERT, UPDATE, DELETE). Схему применяет консольный скрипт `init-db.php`.

## Ветки и порядок работы

- `mvp` рабочая ветка. Этапы с 3 по 9 из спецификации пишутся в ней. После каждого завершённого этапа ставится аннотированный тег `mvp-etap-N`, например `git tag -a mvp-etap-3 -m "Этап 3: публикация"`.
- Участники работают в своих ветках от `mvp` и вносят изменения через pull request в `mvp`. Прямые коммиты в `mvp` делает только владелец.
- `full` хранит полный первоначальный замысел и всё остальное. Её обновляют только слиянием `mvp` в `full`: никогда наоборот и без rebase. Нужный файл из `full` переносится в `mvp` командой `git checkout full -- путь` отдельным коммитом.
- `main` отдельная ветка для будущего pull request, сейчас в ней только начальный коммит.
