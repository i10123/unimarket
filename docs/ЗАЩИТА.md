# УниМаркет: шпаргалка к защите

Всё, что сделано на 6 ноября 2026, в одном файле. Сначала прочитай разделы 1–4 (что и как работает), потом 5–7 (азы PHP, SQL и JS), в конце 8 — вопросы преподавателя.

## 1. Проект за 30 секунд

Учебный маркетплейс: студенты публикуют конспекты и покупают их за внутренние баллы. Стек: **HTML + CSS + JavaScript** (то, что видит браузер), **PHP** (сервер, логика), **MySQL** (база данных).

| Готово | Ещё нет |
|---|---|
| Лендинг (Grid на ПК, Flexbox на телефоне) | Публикация материалов и загрузка файлов |
| Регистрация по логину и паролю → сразу вход | Каталог с поиском и страница материала |
| Вход, выход, сессия | Покупка, резерв на 24 часа, замена файла |
| Страница каталога: показывает логин и баланс из БД | Оценки, избранное, профиль |
| База MySQL из 7 таблиц | |
| Автотест доступа `tests/auth.php` | |

Требования — [mvp/SPECIFICATION.md](mvp/SPECIFICATION.md).

## 3. Как работает регистрация — путь одного клика

```text
Браузер (auth.js) ──fetch POST /api/auth──▶ router.php ──▶ backend/auth.php
                                                              │ проверки
                                                              ▼
                     ◀──── JSON {user, csrf} ────── AuthHandler.php ──SQL──▶ MySQL
```

1. **Открытие страницы.** `auth.js` делает `GET /api/auth` и получает **CSRF-токен** (случайную строку из сессии). Пока токена нет, кнопка неактивна.
2. **Отправка.** Пользователь жмёт «Создать аккаунт». `otpravitFormu()` отменяет обычную отправку (`preventDefault`) и шлёт JSON `{action: "register", login, password}` с токеном в заголовке `X-CSRF-Token`.
3. **router.php** видит адрес `/api/auth` и передаёт запрос в `backend/auth.php`.
4. **auth.php** проверяет по очереди: метод POST → токен совпадает с сессией → размер и формат JSON → лимит попыток (20 за 15 минут) → логин 3–32 символа (латиница, цифры, _ . -), пароль от 8 символов.
5. **AuthHandler::register()** в одной **транзакции** создаёт строку в `users` (с хешем пароля) и строку в `wallets` (баланс 0). Если вторая вставка упадёт — откатится и первая.
6. **auth.php** меняет идентификатор сессии, записывает в неё `user_id` и отвечает JSON с пользователем (код 201).
7. **auth.js** получает ответ и переходит на `/pages/catalog.html`.
8. **router.php** пускает в каталог, потому что в сессии есть `user_id`. Без входа он перенаправит на страницу входа.
9. **account.js** снова делает `GET /api/auth` и выводит логин и баланс.

Вход — то же самое, только `AuthHandler::login()` ищет пользователя по логину и сравнивает пароль с хешем через `password_verify`.

## 4. Как всё настроено

- **Запуск:** `scripts/start.ps1`. Скрипт при первом запуске скачивает MySQL 8.4 с официального сайта (проверяет контрольную сумму) в `%LOCALAPPDATA%\UniMarket\runtime`, создаёт каталог данных `storage/mysql8`, запускает MySQL на `127.0.0.1:3306`, применяет `schema.sql` и запускает встроенный PHP-сервер на `http://127.0.0.1:8000`. Остановка — `scripts/stop.ps1`.
- **Почему нельзя открыть HTML двойным кликом или через Live Server:** тогда нет PHP, а значит нет API, сессий и базы.
- **Два пользователя MySQL:**
  - `root` — администратор, пароль в `storage/mysql-admin.json`, нужен только скриптам для создания таблиц;
  - `unimarket` — пользователь сайта, пароль в `config/local.php`. Может только читать и менять данные (SELECT, INSERT, UPDATE, DELETE), но не удалять таблицы. Если сайт взломают, структуру БД испортить не получится.
- **Секреты не в Git:** `.gitignore` исключает `config/local.php` и всю папку `storage/`.
- **Просмотр базы:** Beekeeper Studio, подключение «УниМаркет — MySQL» (127.0.0.1:3306, база `unimarket`).

### База данных: 7 таблиц

| Таблица | Что хранит | Используется сейчас |
|---|---|---|
| `users` | id, логин (уникальный, он же имя продавца), хеш пароля, курс | ✅ |
| `wallets` | user_id, доступные баллы, баллы в резерве (оба ≥ 0) | ✅ |
| `materials` | автор, название, описание, предмет, курс, цена, статус | этап 3 |
| `purchases` | покупатель, материал, цена, статус, срок 24 ч, проблема, оценка 1–5 | этап 5 |
| `files` | файлы материала **или** замена в покупке | этап 3 |
| `favorites` | пары «пользователь — материал» | этап 8 |
| `point_entries` | история изменений баланса | этап 3 |

Связи: пользователь 1:1 кошелёк; пользователь 1:N материалы; покупки связывают пользователей и материалы (M:N).

### Защита (частые вопросы)

| Угроза | Что сделано | Где |
|---|---|---|
| Утечка паролей из БД | Хранится не пароль, а хеш **Argon2id**: из него пароль не восстановить | `AuthHandler::register` |
| SQL-инъекция | Запросы с `?` — данные передаются отдельно от SQL (`prepare` + `execute`) | все запросы |
| Чужой сайт шлёт запрос от имени пользователя (CSRF) | Секретный токен в заголовке сверяется с сессией | `auth.php` |
| Перебор паролей | 20 попыток за 15 минут с одного IP | `checkAuthLimit()` |
| Кража сессии | Новый id сессии после входа; cookie `HttpOnly` (JS не прочитает) и `SameSite` | `auth.php`, `bootstrap.php` |
| Доступ к служебным файлам | router отдаёт только известные страницы и `assets/`, остальное — 404 | `router.php` |
| Отрицательный баланс | `CHECK (available >= 0)` в самой базе | `schema.sql` |
| Половина данных при сбое | Транзакция: пользователь и кошелёк создаются вместе | `AuthHandler::register` |

## 5. PHP — минимум, чтобы читать наш код

PHP выполняется **на сервере**. Браузер получает только результат (HTML или JSON), сам код PHP он не видит.

```php
<?php                          // начало PHP-кода
declare(strict_types=1);       // строгие типы: в int нельзя передать "5"

$login = 'denis';              // переменные начинаются с $
$count = 0;
$user = ['id' => 1, 'login' => 'denis'];  // массив «ключ => значение» (как объект в JS)
echo $user['login'];           // вывод; доступ по ключу через [ ]

'Привет, ' . $login            // склейка строк — точкой (в JS это +)

if ($count >= 20) { ... } elseif (...) { ... } else { ... }
foreach ($items as $item) { ... }          // как for...of в JS

function isValidLogin(string $login): bool // типы параметров и результата
{
    return preg_match('/^[a-z0-9_.-]{3,32}$/D', $login) === 1;  // проверка регулярным выражением
}

$a ?? 'по умолчанию'          // если $a нет или null — взять правое значение
$_SESSION['csrf'] ??= '...';  // записать, только если ещё пусто
```

**Сравнение:** `===` — строго (как в JS), `!==` — строго не равно.

**Суперглобальные массивы** — PHP заполняет их сам:
- `$_SERVER['REQUEST_METHOD']` — GET или POST;
- `$_SESSION` — данные сессии, живут между запросами одного пользователя (у нас `user_id` и `csrf`).

**Классы** (`AuthHandler.php`):
```php
final class AuthHandler
{
    public function __construct(private PDO $db) {}   // при создании сохраняем подключение в $this->db

    public function login(string $login, string $password): ?int   // ?int = число или null
    {
        $query = $this->db->prepare('SELECT ...');      // -> вызывает метод объекта (в JS — точка)
    }
}
$auth = new AuthHandler(db());   // создать объект
$auth->login($login, $password);
AuthHandler::DUMMY_HASH          // :: — константа класса
```

**Ошибки:** `try { ... } catch (PDOException $error) { ... }` — как в JS. `throw` выбрасывает ошибку.

**Подключение файлов:** `require __DIR__ . '/bootstrap.php';` — вставить код другого файла (`__DIR__` — папка текущего файла).

**Работа с БД через PDO:**
```php
$query = db()->prepare('SELECT id FROM users WHERE login = ?');  // SQL с местом под значение
$query->execute([$login]);                                       // значение отдельно → нет инъекции
$user = $query->fetch();                                         // одна строка как массив или false
```

**Ответ браузеру:** `respond(['user' => ...], 201)` в `bootstrap.php` ставит код ответа, превращает массив в JSON (`json_encode`), выводит его и завершает скрипт.

## 6. SQL — минимум

```sql
-- Создать таблицу (schema.sql)
CREATE TABLE users (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,  -- уникальный номер, растёт сам
    login VARCHAR(32) NOT NULL UNIQUE,              -- строка, обязательна, без повторов
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP  -- дата по умолчанию — сейчас
);

INSERT INTO users (login, password_hash) VALUES (?, ?);   -- добавить строку
SELECT id, login FROM users WHERE login = ?;              -- найти
UPDATE wallets SET available = 100 WHERE user_id = ?;     -- изменить
DELETE FROM favorites WHERE user_id = ? AND material_id = ?;  -- удалить

-- Соединить две таблицы по связи (bootstrap.php, currentUser)
SELECT u.id, u.login, w.available, w.reserved
FROM users u
JOIN wallets w ON w.user_id = u.id
WHERE u.id = ?;
```

| Термин | Простыми словами |
|---|---|
| PRIMARY KEY (PK) | Уникальный номер строки |
| FOREIGN KEY (FK) | Ссылка на строку другой таблицы; нельзя сослаться на несуществующую |
| UNIQUE | Повторы запрещены (два одинаковых логина не сохранятся, ошибка 1062) |
| CHECK | Правило для значения (баланс ≥ 0, ошибка 3819) |
| INDEX | «Оглавление» для быстрого поиска |
| Транзакция | Группа запросов: выполняются все или ни одного (`beginTransaction` → `commit` / `rollBack`) |

## 7. JavaScript в проекте

```js
// async/await: ждём ответ сервера, не замораживая страницу
async function zagruzitAkkaunt() {
  const response = await fetch("/api/auth");   // запрос к PHP
  const data = await response.json();          // JSON → объект JS
  if (!response.ok) {                          // ok = код 200–299
    throw new Error(data.error);               // текст ошибки пришёл от PHP
  }
}

fetch("/api/auth", {
  method: "POST",
  headers: { "Content-Type": "application/json", "X-CSRF-Token": csrf },
  body: JSON.stringify({ action: "logout" }),  // объект → JSON-строка
});
```

- `document.documentElement.dataset.ekran = "vhod"` пишет атрибут `data-ekran` на `<html>`. CSS по нему показывает нужную форму: `[data-ekran="vhod"] #vhod { display: flex; }`.
- `auth.js` подключён в `<head>` без `defer`, чтобы выбрать форму **до** отрисовки, без мигания.
- JS только помогает пользователю. Настоящие проверки делает PHP: JS в браузере можно отключить или подделать.

## 8. Вопросы, которые могут задать

**Почему Grid и Flexbox?** Требование: Grid на ПК/планшете (`.material-grid` — `repeat(4, minmax(0, 1fr))`, на 1199px — 2 колонки), на телефоне до 768px media-запрос включает `display: flex; flex-direction: column`. Подробный разбор и мини-практика — в [learning/PROGRESS.md](learning/PROGRESS.md#разбор-для-защиты).

**Где хранится пароль?** Нигде. В БД лежит хеш Argon2id. При входе `password_verify` хеширует введённый пароль и сравнивает.

**Что будет при вводе `' OR 1=1 --` в логин?** Ничего: значение передаётся через `?` и считается обычной строкой. Это проверяет автотест.

**Зачем два пользователя MySQL?** Принцип минимальных прав: сайт работает под `unimarket`, который не может менять структуру БД.

**Почему вошедший пользователь не видит лендинг?** `router.php`: гостю — лендинг и формы, вошедшему — каталог.

**Что такое сессия?** Сервер хранит данные пользователя (у нас — в `storage/sessions`), а браузер — только cookie с номером сессии.

**Как проверить, что всё работает?** Запустить `scripts/start.ps1`, затем `php tests/auth.php`. Должна появиться строка `OK: ...`. Тест сам создаёт и удаляет временный аккаунт.

**Почему логин, а не email?** Писем у нас нет, адрес не подтверждается и не нужен для восстановления — значит, email был бы просто логином. Пароль меняется в настройках по старому паролю (этап 8).
