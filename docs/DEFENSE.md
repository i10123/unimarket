# Защита MVP «УниМаркет»

Это сценарий короткой демонстрации и ответы на основные вопросы о проекте. Актуальные требования находятся в [спецификации MVP](mvp/SPECIFICATION.md).

## 1. Как представить проект за минуту

«УниМаркет» — учебный маркетплейс. Студенты смогут публиковать конспекты, решения задач и шпаргалки, а покупать их за внутренние баллы. Реальных денег в проекте нет.

Сейчас готов фундамент MVP: лендинг, регистрация в два шага, вход и выход, сессии, кошелёк пользователя и база данных. При регистрации пользователь получает 100 баллов. Следующий этап — публикация материалов с файлами, затем полноценный каталог и покупка.

Стек выбран без лишних зависимостей: HTML, CSS, JavaScript, PHP 8.3 и MySQL 8.4. Это позволяет показать всю логику работы приложения, а не скрыть её за фреймворком.

## 2. Что показать на демонстрации

1. Открыть главную страницу. Показать адаптивный лендинг и ссылки на вход и регистрацию.
2. Перейти к регистрации. На первом шаге ввести логин и пароль, принять правила. Объяснить, что логин проверяется, но аккаунт ещё не создаётся.
3. На втором шаге заполнить профиль либо пропустить его. После отправки открывается каталог: аккаунт создан, пользователь уже вошёл в систему, баланс равен 100.
4. Показать имя пользователя и баланс на странице каталога. Объяснить, что каталог на этом этапе — начальная закрытая страница, а не имитация готового магазина.
5. Выйти, затем войти тем же логином и паролем. Показать, что сессия завершается и новый вход работает.
6. При необходимости открыть phpMyAdmin или выполнить `php scripts/admin.php`, чтобы показать запись пользователя, кошелька и историю начисления в БД.

Для демонстрации нужны запущенные Apache, PHP и MySQL в Open Server Panel и адрес `http://unimarket.local`. Полная подготовка окружения описана в [инструкции](../НАСТРОЙКА-ПРОЕКТА.md).

## 3. Как устроен проект

```text
Браузер
  │  HTML, CSS, JavaScript
  ▼
.htaccess → router.php
  │             │
  │             ├─ страницы из pages/
  │             └─ /api/auth → backend/auth.php
  ▼
backend/bootstrap.php → PDO → MySQL
                         │
                         └─ config/local.php
```

| Область | Где находится | Назначение |
| --- | --- | --- |
| Интерфейс | `index.html`, `pages/`, `assets/` | Страницы, стили, JavaScript, иконки и шрифты |
| Серверная логика | `router.php`, `backend/` | Маршрутизация, сессии, API, валидация, авторизация |
| Данные | `database/` | Схема MySQL и описание таблиц |
| Служебные команды | `scripts/` | Создание БД и консоль администратора |
| Локальные данные | `config/`, `storage/` | Пароль БД, сессии, лимиты запросов и будущие файлы |
| Документация | `docs/` | Требования, архитектура и этот сценарий |

`router.php` пропускает только известные страницы и API. Папки с кодом, конфигурацией, схемой базы и пользовательскими файлами напрямую не выдаются браузеру.

## 4. Что хранится в базе

В [схеме](../database/schema.sql) уже семь таблиц:

- `users` — аккаунты и профиль;
- `wallets` — доступные и зарезервированные баллы;
- `point_entries` — история всех изменений баланса;
- `materials` и `files` — будущие учебные материалы и их файлы;
- `purchases` — будущие покупки, резерв и сроки подтверждения;
- `favorites` — избранные материалы.

При регистрации в одной транзакции создаются пользователь, его кошелёк и запись о приветственном начислении. Поэтому нельзя получить пользователя без кошелька или баланс без записи в истории.

## 5. Безопасность, которую можно объяснить

- Пароли не сохраняются в открытом виде: PHP хранит хеш Argon2id.
- Запросы к MySQL параметризованы через PDO, поэтому пользовательский ввод не склеивается с SQL.
- Изменяющие запросы API требуют CSRF-токен, связанный с серверной сессией.
- После входа и выхода идентификатор сессии обновляется.
- Для входа и регистрации действует ограничение попыток с одного IP.
- Секреты БД находятся в `config/local.php`, этот файл и `storage/` исключены из Git.
- Будущие загруженные материалы будут скачиваться через PHP только после проверки прав пользователя, а не напрямую из статической папки.

## 6. Текущая граница MVP

Готовы этапы 1–2: окружение, схема БД, регистрация, вход, выход и начальная закрытая страница каталога.

Не нужно выдавать за готовое то, что ещё в работе: публикация материалов, поиск и фильтры, покупка, резерв баллов, скачивание, обращения, оценки, избранное и профиль. Их правила уже зафиксированы в спецификации, а структура БД подготовлена заранее.

Следующий ближайший этап — публикация материала: форма, техническая проверка до пяти файлов, ограничение «не более пяти материалов в день» и начисление 25 баллов за бесплатный материал.

## 7. Частые вопросы и короткие ответы

### Почему без фреймворка?

Проект небольшой и учебный. Обычные HTML, CSS, JavaScript и PHP делают архитектуру прозрачной: на защите можно проследить путь от формы до записи в БД. Когда появится реальная потребность в компонентах, сборке или сложной навигации, стек можно пересмотреть.

### Почему есть таблицы для ещё неготовых функций?

Покупка и файлы связаны с балансом, сроками и правами доступа. Схема была спроектирована заранее, чтобы последующие этапы не потребовали разрушительной переделки уже работающей авторизации и кошелька. Нереализованные таблицы пока не используются приложением.

### Как защищены баллы от двойного списания?

Правило описано в спецификации и поддержано ограничением: у пары «покупатель — материал» будет только одна покупка. На этапе покупки списание, резерв и запись в истории будут выполняться одной транзакцией. Сам этап покупки пока не реализован.

### Почему каталог закрыт для гостя?

Это пока сознательное временное решение: текущая страница каталога показывает данные авторизованного пользователя. Открывать ли настоящий каталог гостям — зафиксированный открытый вопрос MVP, который будет решён на этапе каталога.

### Есть ли веб-админка?

Нет. Веб-админка и модерация не входят в MVP. Для владельца предусмотрена локальная консоль `scripts/admin.php`: просмотр пользователей, сброс пароля и удаление аккаунта.

### Что будет проверяться в следующем этапе?

Корректная публикация материала с обязательным типом, максимум пятью файлами, дневным лимитом, а также одноразовое начисление 25 баллов за бесплатный материал. Затем — отображение только опубликованных материалов в каталоге.
