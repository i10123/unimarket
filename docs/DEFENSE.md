# Защита MVP «УниМаркет»

Сценарий короткой демонстрации и ответы на основные вопросы. Актуальные требования — в [спецификации MVP](mvp/SPECIFICATION.md).

## 1. Как представить проект за минуту

«УниМаркет» — учебный маркетплейс. Студенты публикуют конспекты, решённые задачи и шпаргалки, а покупают их за внутренние баллы. Реальных денег нет. При регистрации студент получает 100 баллов, за бесплатный материал — 25, а за платный получает его цену при продаже.

Покупка защищена: баллы покупателя уходят в резерв, файлы открываются сразу, в первые 24 часа можно подтвердить покупку или сообщить о проблеме. Продавец заменяет файл или возвращает баллы; если никто ничего не делает, срок истекает и система сама закрывает покупку.

Стек без лишних зависимостей: HTML, CSS, JavaScript, PHP 8.3 и MySQL 8.4.

## 2. Что показать на демонстрации

Перед показом выполнить `php scripts/seed.php`: появятся 10 демо-пользователей и 50 их материалов (по одному файлу .md). Покупки и оценки показываются на лету: войти под одним демо-пользователем, купить материал другого, затем войти под вторым и ответить в «Мои продажи».

1. Главная: адаптивный лендинг. Регистрация в два шага (новый аккаунт: 100 баллов).
2. Каталог: поиск, фильтры по типу, предмету, курсу и цене, сортировка, «Показать ещё».
3. Страница материала → «Купить»: баланс уменьшился, баллы в резерве, появилась ссылка на файл.
4. «Мои покупки»: скачать файл, «Подтвердить» или «Проблема с файлом», оценка продавца.
5. Войти под другим демо-пользователем: «Мои продажи» — ответить на обращение (заменить файл или вернуть баллы).
6. «Разместить»: публикация с файлами; бесплатный материал даёт +25 баллов.
7. Профиль: история баллов, настройки, смена пароля. Консоль `php scripts/admin.php`: список пользователей, статистика, удаление.

Нужны запущенные Apache, PHP и MySQL в Open Server Panel и адрес `http://unimarket.local`. Подготовка окружения — в [инструкции](../НАСТРОЙКА-ПРОЕКТА.md).

## 3. Как устроен проект

```text
Браузер (HTML, CSS, JS-модули)
  │
.htaccess → router.php
  │             ├─ страницы из pages/ (гостю — одни, вошедшему — другие)
  │             └─ /api/<имя> → backend/api/<имя>.php
  ▼
runApi() → классы Market, Deals, AuthHandler, FileStore, Points → PDO → MySQL
```

| Область | Где находится | Назначение |
| --- | --- | --- |
| Интерфейс | `index.html`, `pages/`, `assets/` | Страницы, стили, JavaScript, иконки и шрифты |
| API | `backend/api/` | Пять адресов: auth, market, deals, account, download |
| Логика | `backend/*.php` | Каталог, покупки, баллы, файлы, проверка полей |
| Данные | `database/` | Схема MySQL и описание таблиц |
| Служебные команды | `scripts/` | Создание БД, тестовые данные, консоль администратора |
| Локальные данные | `config/`, `storage/` | Пароль БД, сессии, лимиты, загруженные файлы |

## 4. Что хранится в базе

Семь таблиц ([схема](../database/schema.sql)): `users`, `wallets`, `materials`, `files`, `purchases`, `favorites` и `point_entries` — история всех изменений баллов. Покупка, резерв, выплата, возврат и награда выполняются в одной транзакции вместе с записью в историю, поэтому остаток всегда равен сумме записей. Связи ON DELETE CASCADE: удаление пользователя в консоли убирает и его данные.

## 5. Безопасность, которую можно объяснить

- Пароли — хеш Argon2id; SQL — только с параметрами (PDO); пользовательский текст на страницах вставляется как текст, а не как HTML.
- Изменяющие запросы требуют CSRF-токен из серверной сессии; идентификатор сессии обновляется при входе и выходе.
- Вход, регистрация и смена пароля ограничены по числу попыток с одного IP.
- Права проверяет PHP: нельзя купить свой материал, купить дважды, подтвердить чужую покупку, ответить на обращение после срока.
- Принимается любой формат (до 10 файлов по 15 МБ), поэтому защита не в списке форматов: файл никогда не выполняется, лежит вне доступа браузера под случайным именем без расширения и отдаётся через `/api/download` как вложение (`octet-stream`) только автору и покупателю.
- Двойной щелчок не спишет баллы дважды: кошелёк блокируется на время транзакции, а у пары «покупатель — материал» одна покупка (уникальный ключ).
- Секреты БД — в `config/local.php`, он и `storage/` не попадают в Git. Приложение подключается к БД пользователем только с правами на данные.

## 6. Границы MVP

Нет почты и восстановления пароля (страница честно сообщает, что функция не готова), чатов, услуг, заявок, веб-админки, текстовых отзывов, корзины и реальных денег. Подробно — раздел «Не входит в MVP» [спецификации](mvp/SPECIFICATION.md).

## 7. Частые вопросы и короткие ответы

### Почему без фреймворка?

Проект небольшой и учебный. Обычные HTML, CSS, JavaScript и PHP делают архитектуру прозрачной: путь от формы до записи в БД можно проследить файл за файлом.

### Как защищены баллы от двойного списания?

Покупка выполняется в транзакции: кошелёк покупателя блокируется, проверяется остаток, создаётся покупка и запись в истории. Повторный запрос упирается в уникальный ключ «покупатель — материал» и баллы не списывает.

### Как работают 24 часа без планировщика?

Отдельной задачи по расписанию нет. При первом обращении любого пользователя к сайту (`currentUser()`) просроченные покупки закрываются: без обращения — баллы уходят продавцу, с обращением без ответа — возвращаются покупателю. Результат такой же, как у планировщика, и повторный вызов ничего не меняет.

### Почему каталог закрыт для гостя?

Гостю показан лендинг с демонстрационными карточками; настоящий каталог, покупки и баллы доступны после регистрации.

### Есть ли веб-админка?

Нет. Для владельца есть локальная консоль `scripts/admin.php`: список пользователей, подробная статистика каждого и удаление.
