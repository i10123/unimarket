# Порядок разработки связанных разделов

Сначала собираем интерфейс и его понятные локальные действия. Затем подключаем PHP и базу данных вместе с backend-частью команды. Переход по ссылке между HTML-страницами и настоящее создание аккаунта — разные уровни готовности.

## Почему такой порядок

Двигаемся от простых элементов к сложным состояниям. При этом заканчиваем пользовательский путь: например, каталог сам по себе недостаточен — после него нужна страница материала, а покупку считаем завершённой только после появления материала у покупателя.

Для каждого этапа повторяется цикл: HTML → десктопный CSS → планшет → телефон → поведение → проверка. Не откладываем адаптивность всех страниц на конец проекта.

| Этап | Какие экраны делаем | Что используем повторно | Какой результат закрываем |
|---|---|---|---|
| 0 | Подготовка файлов, шрифт, цвета, общие правила | Параметры из Figma | Есть основа для всех страниц |
| 1 | Лендинг `01` | Контейнер, кнопки, карточка, FAQ, подвал | Посетитель понимает проект и видит пути к входу и каталогу |
| 2 | Помощь `19` и страница ошибки `20` | Шапка, подвал, текстовые блоки | Работает справочный раздел; есть оформление ошибки маршрута |
| 3 | Вход `03`, регистрация `02` | Кнопки, поля, подписи, ошибки | Закрыт интерфейс входа и создания аккаунта |
| 4 | Восстановление `04` → код `05` → новый пароль `06` → успех `07` | Формы этапа 3 | Весь путь восстановления ведёт обратно ко входу |
| 5 | Каталог материалов `08.1` → материал `09` → автор `13` | Карточка лендинга, Grid, поиск, фильтры | Можно найти материал и изучить его до покупки |

Номера в таблице — номера макетов Figma, а не последовательность занятий. Отдельные формы и состояния одного экрана не обязательно превращать в отдельные HTML-страницы: например, кабинет может переключать разделы, а подтверждение выхода открываться диалогом.

## Карта переходов

- Гость: лендинг → вход или регистрация → каталог.
- Потерял пароль: вход → восстановление → код → новый пароль → успех → вход.
- Ищу материал: каталог → материал → автор → материал → покупка → мои материалы.
- Хочу вернуться позже: каталог или материал → избранное → материал.
- Публикую материал: кабинет → размещение → на проверке → решение администратора → опубликовано → каталог.
- Нужна помощь: лендинг или каталог заявок → создать заявку → мои заявки → отклики → исполнитель → чат → завершение → отзыв.
- Предлагаю помощь: каталог заявок → чужая заявка → отклик → выбор заказчика → чат → результат → подтверждение.
- Заказываю услугу: каталог услуг → услуга → автор или обсуждение → чат → согласованный заказ → завершение.

Это предлагаемые связи реализации по назначению экранов. Не все переходы проверены как реакции Figma-прототипа. У корневого фрейма лендинга список реакций пуст; это не означает отсутствия реакций у его дочерних кнопок.

## Что значит «этап закончен»

1. Все его экраны связаны между собой и с предыдущим этапом; есть понятный путь назад.
2. Одинаковые элементы используют одинаковые классы и общие стили.
3. Работают десктопная, планшетная и телефонная раскладки.
4. Проверены нормальное состояние, пустой результат и ошибка там, где они возможны.
5. Можно пройти сценарий клавиатурой, прочитать подписи полей и увидеть фокус.
6. Ты можешь объяснить главные решения и изменить их без копирования готового решения.

Если следующий раздел ещё не создан, ссылка на него фиксируется в списке будущих переходов. До появления целевого файла такая ссылка считается незавершённой, а не «готовой навигацией». Не создаём десятки пустых страниц ради видимости связности.

## Где начинается работа сервера

Для практической по вёрстке не нужны PHP, MySQL, настоящее списание баллов и отправка писем. Интерфейсные демонстрации допустимы, если они явно описаны как демонстрации.

Для работающего приложения PHP должен проверять доступ, вход, владение публикациями и заказами. Баланс, покупка, начисление и доступ к файлу подтверждаются сервером, а не значением в JavaScript или localStorage. Покупка должна выполняться согласованно на стороне базы; отзыв должен быть связан с реальной завершённой сделкой.

В README упомянута корзина, но в просмотренном списке Desktop отдельный экран корзины не найден. Это открытый вопрос продуктового объёма: не добавляем выдуманный макет и не считаем корзину уже спроектированной. Пустые состояния, ошибки покупки и часть серверных результатов также нужно детализировать перед соответствующим этапом.

Страница 404 сначала будет обычным демонстрационным файлом. Автоматическая выдача её для неизвестного адреса и HTTP-статус 404 появятся при настройке сервера.
