# HTML: что и когда использовать

HTML описывает содержимое и его назначение. CSS определяет внешний вид и расположение. JavaScript меняет поведение. Сначала страница должна читаться в правильном порядке без оформления.

## Минимальный словарь

| Понятие | Что означает |
|---|---|
| Тег | Обозначение элемента, например `header` или `p` |
| Элемент | Сам объект документа: тег, его атрибуты и содержимое |
| Атрибут | Уточнение элемента: `href`, `class`, `id`, `type` |
| Родитель / ребёнок | Вложенность: карточка содержит название, описание и цену |
| Класс | Повторяемое имя для CSS; несколько карточек могут иметь один класс |
| ID | Уникальное имя одного элемента; нужно, например, для ссылки на раздел |
| DOM | Дерево элементов страницы, с которым работает браузер и JavaScript |

Открывающий и закрывающий теги образуют контейнер. У `img`, `input`, `meta`, `link` нет закрывающего тега. Следи за вложенностью: закрывать контейнеры нужно в обратном порядке их открытия.

## Основа файла

| Что добавить | Зачем | Проверка |
|---|---|---|
| Объявление `doctype` | Современный режим отображения HTML |
| `html`, язык `ru` | Корень документа и язык текста | Средства чтения понимают язык |
| `head` | Служебная информация, не содержимое страницы |
| `meta` с UTF-8 | Правильная кириллица | Вместо букв нет непонятных символов |
| `meta` viewport | Соответствие ширины страницы экрану телефона | Эмулятор телефона не показывает уменьшенный десктоп |
| `title` | Название вкладки | Во вкладке написано «УниМаркет…» |
| `link` для CSS | Подключение внешнего файла стилей | В Network запрос к CSS проходит без 404 |
| `body` | Видимое содержимое страницы |
| `script` с `src` и `defer` | Подключение JS с выполнением после разбора HTML | DOM доступен обработчикам |

Подключай CSS в порядке: токены → базовые правила → общие компоненты → стили конкретной страницы. При одинаковой специфичности и прочих равных более позднее правило выигрывает.

## Теги для нашего лендинга

| Задача | Тег | Как применить |
|---|---|---|
| Шапка сайта | `header` | Бренд и действия входа |
| Навигация | `nav` | Группа переходов по сайту; несколько nav нужно различать доступными названиями |
| Основное содержимое | `main` | Один основной видимый main на странице |
| Смысловой раздел | `section` | Материалы, FAQ; у раздела обычно есть заголовок |
| Самостоятельная карточка | `article` | Один материал со своим названием |
| Подвал | `footer` | Бренд и полезные ссылки |
| Главный заголовок | `h1` | «Учиться легче вместе» |
| Заголовок раздела | `h2` | «Полезное уже ждёт в каталоге», «Частые вопросы» |
| Заголовок карточки | `h3` | Название материала внутри раздела |
| Абзац | `p` | Описание проекта и материала |
| Список | `ul`, `li` | Однотипные ссылки или элементы перечисления |
| Обычный контейнер | `div` | Объединение элементов ради раскладки, если отдельного смыслового тега нет |
| Фрагмент текста | `span` | Цена, рейтинг, выделение части строки |
| Переход | `a` | Войти, зарегистрироваться, открыть материал |
| Действие | `button` | Избранное, раскрытие меню |
| Изображение | `img` | Экспортированная иконка или другой реальный графический ресурс |
| Раскрываемый ответ | `details`, `summary` | FAQ без собственного JS |

Название `h1` в Figma не обязывает использовать тег h1. Размер не выбирает уровень заголовка: выбирай уровень по смыслу, а размер — через CSS.

## Ссылка и кнопка

- **Переход на другую страницу или к разделу** — ссылка с осмысленным `href`.
- **Изменение состояния текущей страницы** — кнопка.
- Ссылка может выглядеть как большая зелёная кнопка. Её назначение от этого не меняется.
- Внутри формы у обычной кнопки действия явно задавай `type="button"`, иначе она может отправить форму. У отправляющей кнопки — `type="submit"`.
- Не помещай кнопку избранного внутрь ссылки, охватывающей всю карточку. Сделай ссылкой название или отдельную область, а избранное оставь самостоятельной кнопкой.
- Не делай кликабельным `div`, если уже есть подходящие ссылка или кнопка: у них изначально есть нужное поведение клавиатуры.

## Пути к файлам

Относительный путь считается от текущего HTML-файла. Если `index.html` лежит в корне, путь до CSS начинается с `assets/…`, а путь до страницы входа — с `pages/…`. Если сам HTML уже лежит в `pages`, выход к общей папке assets начинается с `../assets/…`.

Используй `/` в адресах HTML. Путь вида `D:\...` не подходит как адрес ресурса сайта. Имя, регистр и расширение должны совпадать с реальным файлом. На одном компьютере ошибка регистра может быть незаметна, а на сервере сломать загрузку.

`href="#"` — не рабочий переход в раздел: он может переместить страницу к началу. Для перехода к FAQ нужен настоящий ID соответствующего элемента. Если целевой страницы ещё нет, пометь переход как незавершённый в своём списке задач.

## Изображения и доступные названия

Содержательное изображение получает `alt`, объясняющий смысл. Декоративная иконка рядом с тем же текстом — пустой `alt`, чтобы не повторять название. У кнопки с одним сердцем должно быть понятное доступное имя: например, «Сохранить материал „Линейная алгебра“».

Не заменяй экспортированные иконки случайными эмодзи: форма и размеры изменятся. Иконка — это графика; цена и описание — настоящий текст.

`aria-label` даёт элементу доступное имя, если его не объясняет видимый текст. `aria-pressed` подходит для переключателя избранного. `aria-expanded` — для раскрытия меню. Эти атрибуты должны отражать реальное состояние.

## FAQ: сначала самый простой вариант

Каждый вопрос можно оформить через `details`; заголовок вопроса — `summary`; ответ — абзац внутри details. Атрибут `open` задаёт начальное открытое состояние. Переключение работает без собственного JavaScript.

Свойство `open` — логическое: присутствие атрибута открывает пункт. Запись со строкой «false» не означает закрытое состояние; атрибут нужно убрать.

Обычные details позволяют открыть несколько ответов. Ограничение «только один открыт» — отдельная задача, если оно понадобится. Не усложняй первый проход незаявленным поведением.

В макете виден текст только первого ответа. Остальные ответы нужно подготовить как учебный контент, а не выдавать за дословно извлечённые из Figma.

## Формы — для следующих занятий

| Тег / атрибут | Задача |
|---|---|
| `form` | Объединяет поля и отправку |
| `label`, `for`, `id` | Связывают видимую подпись с конкретным полем |
| `input` | Однострочный ввод |
| `type="email"` / `password` | Подходящий режим и базовое поведение поля |
| `name` | Имя поля при отправке формы |
| `required`, `minlength`, `maxlength` | Базовые ограничения ввода |
| `autocomplete` | Подсказка браузеру о назначении поля |
| `textarea` | Многострочное описание |
| `select`, `option` | Выбор из списка |
| `fieldset`, `legend` | Группа связанных полей и её название |

Placeholder — пример ввода, он не заменяет постоянную подпись. Проверка браузером помогает пользователю, но сервер всё равно проверяет данные повторно.

## Самопроверка HTML

1. Отключи стили: порядок чтения остаётся понятным.
2. Проверь заголовки: один основной h1, затем разделы h2, внутри карточек h3.
3. Нажимай Tab: ссылки и кнопки доступны, порядок соответствует чтению.
4. Проверь каждый ID: нет повторений; ссылки на разделы ведут к существующим ID.
5. Проверь DevTools → Network: нет пропавших файлов.
6. Измени название одной карточки: остальная структура не должна зависеть от текста.
