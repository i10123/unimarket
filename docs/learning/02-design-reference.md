# Параметры дизайна для первой страницы

Источник: Figma «УниМаркет — дизайн», чтение 21 октября 2026 через Figwright. Размеры и раскладки ниже получены из `get_design_context`, цвета — из переменных, общие текстовые стили — из `get_styles`. Скриншоты использованы для визуальной сверки, не для измерений.

Страница стандартов подписана в макете как актуализированная 17 октября 2026. В отдельных местах реальный экран отличается от общего описания; различия отмечены ниже. Это снимок состояния дизайна, а не автоматически обновляемая документация.

## Цвета

В Figma есть базовые значения Primitives и смысловые Tokens. В CSS удобнее обращаться к смысловым переменным: фон страницы — `--color-bg`, основной текст — `--color-ink`. Само наличие переменной в Figma не создаёт её в CSS: ты объявляешь её в файле токенов.

## Шрифт и текст

Основная гарнитура — **Manrope**. Используются насыщенности 400, 500, 600, 700, 800. Для начала выбери один способ подключения: локальные WOFF2 в `assets/fonts` или подключение гарнитуры из внешнего источника. Проверь в браузере, что используется Manrope, а не запасной системный шрифт.

| Стиль Figma | Размер | Насыщенность | Межстрочный интервал |
|---|---:|---:|---:|
| Display | 44 px | 800 | 1.4 ≈ 61.6 px |
| H1 | 32 px | 800 | 1.4 ≈ 44.8 px |
| H2 | 24 px | 700 | 1.4 ≈ 33.6 px |
| H3 | 18 px | 700 | 1.4 ≈ 25.2 px |
| Body | 15 px | 400 | 1.4 = 21 px |
| Label | 14 px | 600 | 1.4 ≈ 19.6 px |
| Small | 12 px | 500 | 1.4 ≈ 16.8 px |

Названия стилей Figma не определяют HTML-теги. Главный заголовок лендинга размечается `h1`, хотя визуально использует Display 44 px. Название карточки может быть `h3` и иметь размер 24 px.

На самом лендинге есть локальные уточнения:

- Заголовок карточки: 24 px / 28 px, 700.
- Описание карточки: 13 px / 18 px, 400.
- Цена: 16 px / 22 px, 700.
- «Частые вопросы»: 26 px, 700, межстрочный 1.4.
- Текст вопроса: 16 px, 700, межстрочный 1.4.
- Ответ FAQ: 14 px, 400, межстрочный 1.4.

## Отступы и скругления

- Шкала промежутков: 4, 8, 12, 16, 24, 32, 48 px.
- Имена переменных: `--space-4`, `--space-8` и так далее.
- Скругления: `--radius-8`, `--radius-12`, `--radius-16`, `--radius-24`.
- Значения вне шкалы тоже встречаются: например, верхний отступ основного блока 32 px, нижний 40 px; шапка имеет вертикальные поля 20 px. Не заменяй подтверждённое значение ближайшим из шкалы автоматически.

Контрольная арифметика сетки: четыре карточки по 308 и три промежутка по 16 дают 1280 px. В CSS лучше задавать доли свободной ширины, а не вручную назначать всем карточкам ширину 308 px.

Дерево Figma описывает ряд карточек как горизонтальный Auto Layout. Использование Grid для этого ряда — осознанное решение по требованию практической: внешний вид и интервалы сохраняются.

## Что в макете требует осмысленного переноса

1. Общий стандарт говорит «в карточке обычно 24 px», но экземпляры лендинга имеют padding 16. Для первой страницы берём 16; в других экранах проверяем местный контекст.
2. Стандарт просит показывать полные названия и описания. В экземпляре карточки есть техническая настройка обрезания описания до одной строки. Для учебной адаптации выбираем полное отображение, перенос и рост высоты; название не обрезаем. Это сознательное решение, особенно для телефона и длинного текста.
3. Слой кнопки приветствия назван «Разместить материал», но видимый текст и свойство экземпляра — «Создать аккаунт». Ориентируемся на видимый текст, а не старое имя слоя.
4. В подвале есть скрытые старые группы. На десктопе видимы только бренд и ссылки «Каталог», «Правила и помощь». Скрытые подписи не добавляем в вёрстку случайно.
5. Центрирование навигации подвала в Figma сделано отдельным абсолютным слоем. Для сайта воспроизводим его Grid-раскладкой; координаты Figma не переводим в набор `left` и `top`.
6. Motion-контекст лендинга прочитан полностью: посещено 135 узлов, анимаций нет. Сложную анимацию не добавляем как обязательную работу.

## Телефон: подтверждённое и предложенное

Фрейм `191:3065`, «01 / Лендинг · Mobile», 390 × 2564 px. Он уже существует в файле.

Подтверждено из дерева макета:

- Шапка 64 px, поля по бокам 16, вертикальные 10, gap 8. Бренд, «Войти» и кнопка меню. Кнопки 44 px высотой; меню 44 × 44.
- Основная ширина 358 px при экране 390; поля по 16. Верхний отступ main 24, нижний 32, промежутки 20.
- Главный заголовок 32 px / 40 px, 800; заголовок приветствия 26 px / 34 px, 800.
- Приветствие идёт колонкой; padding 20 по вертикали и 16 по горизонтали; gap 20. Текст, действие, плашка баллов располагаются друг под другом.
- Карточки — одна колонка, gap 16. В снимке ширина 358, высота 264 px; на сайте допускаем рост при длинном содержимом.
- Блок заявки — колонка с padding 20 / 16, gap 20.
- FAQ сохраняет gap 8, длинные вопросы переносятся.
- Подвал — колонка, padding 24, gap 12; бренд и ссылки. В мобильном варианте ссылки подписаны «Каталог», «Баллы», «Помощь».

Предлагаемые правила реализации, которых нет как готовой CSS-спецификации в Figma:

- От 1200 px: 4 колонки материалов; от 768 до 1199 px: 2 колонки через Grid; до 767 px: Flexbox, одна колонка. Условие телефона записываем как `max-width: 767px`. Это начальные учебные границы, их проверяем по содержимому.
- Для планшета уменьшаем боковые поля до 24–32 px; приветственный блок при нехватке места может становиться одной Grid-колонкой. Планшет остаётся Grid.
- На телефоне главный поток, приветствие, список карточек, блок заявки и подвал используют Flexbox. Ранее заданные Grid-свойства при `display: flex` не управляют раскладкой.
- На ширине меньше 390 px разрешаем дополнительный перенос в шапке, чтобы кнопки не вылезали за экран. Не уменьшаем весь сайт масштабированием.
- Мобильный пункт «Баллы» может вести к FAQ о получении баллов. Это предлагаемый адрес назначения, не подтверждённая реакция прототипа.

Окончательные точки переключения выбираем после проверки реального текста и шрифта. Размер viewport в CSS px важнее бытового названия устройства: широкий телефон в альбомной ориентации может получить планшетную раскладку.
