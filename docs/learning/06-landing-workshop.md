# Первое задание: самостоятельно сверстать лендинг

> Формат этого практикума заменён 22 октября 2026: теперь работаем с готовыми фрагментами и помощью ИИ в файлах. См. [текущий порядок работы](00-current-workflow.md). Подробные шаги ниже сохраняются как справочник; указания «пиши сам» и запрет готового кода больше не действуют.

Цель — страница «Учиться легче вместе», которую ты можешь объяснить и изменить на защите. Здесь нет готовой разметки, CSS-правил всей страницы или написанных за тебя обработчиков. Есть порядок действий, конкретные ориентиры и подсказки.

Исходные фреймы: Desktop `38:2404`, Mobile `191:3065`. [Десктопный снимок](references/38-2404.png), [мобильный снимок](references/191-3065.png). Параметры приведены в [справочнике дизайна](02-design-reference.md).

## 0. Определи границы первого результата

Собираем шапку, главный заголовок, приветственный блок, четыре карточки материалов, блок создания заявки, FAQ и подвал. Делаем десктоп, планшет и телефон.

Формы регистрации, серверный вход, настоящий каталог и покупка относятся к следующим занятиям. Для них сейчас составляем карту переходов. Пока файлов назначения нет, навигация к ним остаётся открытым пунктом, даже если ссылка уже визуально оформлена.

Раздели готовность на две отметки:

- **Вёрстка практической готова:** HTML, Grid/Flexbox, адаптация, проверка и объяснение CSS.
- **Поведение лендинга готово:** дополнительно работает меню, раскрываются FAQ и согласованы доступные переходы. Переключение избранного — отдельное учебное дополнение.

## 1. Подготовь папки и файлы

Существующие README.md и audit.md сохрани. Папка docs/learning уже содержит эти инструкции. Код приложения ты создаёшь сам.

Предлагаемая структура первой страницы:

```text
unimarket/
  index.html
  assets/
    css/
      tokens.css
      base.css
      components.css
      landing.css
    js/
      landing.js
    icons/
    fonts/
  pages/
  docs/
    learning/
```

Порядок действий:

1. Создай assets, внутри — css, js, icons, fonts.
2. Создай index.html в корне: это будущий адрес гостевого лендинга.
3. Создай четыре CSS-файла из дерева.
4. Создай landing.js, когда дойдёшь до интерактивности; заранее заполнять его не нужно.
5. Папку pages можно подготовить пустой. На следующем занятии там появятся login.html, register.html и другие страницы. Не создавай их сейчас только ради заглушек.

Назначение файлов:

| Файл | Что ты в нём пишешь |
|---|---|
| tokens.css | Общие цвета, промежутки, радиусы |
| base.css | Размерная модель, шрифт, фон, базовые правила текста, общий контейнер |
| components.css | Внешний вид повторяемых кнопок, карточек, состояний фокуса |
| landing.css | Размещение секций лендинга и его media-запросы |
| landing.js | Только поведение первой страницы |

Начинающему важнее понимать место каждого правила, чем дробить всё на десятки файлов. Если сомневаешься: общее значение → tokens; общее поведение документа → base; повторяемый элемент → components; положение на этой странице → landing.

**Проверка:** можешь своими словами объяснить назначение каждого файла. Ничего не установлено и не настроено ради ещё не начавшегося backend.

## 2. Подготовь HTML-документ и подключения

1. Добавь doctype, корневой html с русским языком, head и body.
2. Укажи кодировку UTF-8, viewport и название вкладки.
3. Подключи CSS в порядке tokens → base → components → landing.
4. Для начала помести в body один заголовок и открой index.html в браузере.
5. Добавь временное простое изменение внешнего вида через CSS и убедись, что оно применилось; затем убери проверочную правку.
6. Посмотри Network: файлы стилей доступны, кириллица отображается правильно.

Подсказки ищи в начале [HTML-шпаргалки](03-html-cheatsheet.md). Для первого просмотра достаточно открыть HTML-файл. Локальное сохранение данных и PHP позже проверяем через HTTP-сервер.

**Проверка:** вкладка названа правильно, текст читается, стили действительно загружаются.

## 3. Разложи макет на смысловые части

Сначала на бумаге или в заметке запиши вложенность:

1. Шапка: бренд, вход, регистрация.
2. Main: главный заголовок, приветствие, раздел материалов, блок заявки, раздел FAQ.
3. Приветствие: текстовая группа и плашка баллов.
4. Раздел материалов: заголовок и контейнер четырёх article.
5. Карточка: тип и избранное; название и описание; разделитель; автор и цена.
6. FAQ: заголовок и пять раскрываемых пунктов.
7. Подвал: бренд и навигация.

Для HTML удобно объединить заголовок материалов с их списком в section, а заголовок FAQ с вопросами — в другой section. Это смысловая группировка для сайта, даже если в Figma заголовки и списки являются соседними слоями.

Назначь класс каждому контейнеру, которому нужна собственная раскладка. Возможные имена: site-header, container, landing-main, welcome, material-grid, material-card, request-banner, faq, site-footer. Это предложения для названий, не обязательная система.

**Проверка:** для каждого будущего display: grid или display: flex ты знаешь родителя и его непосредственных детей.

## 4. Напиши HTML всех блоков без детализации CSS

1. Добавь header, main, footer в правильном порядке.
2. Главный заголовок — «Учиться легче вместе».
3. В приветствии укажи «Твои знания тоже кому-то нужны.», описание и переход «Создать аккаунт».
4. Плашку баллов заполни тремя строками: «ЗНАНИЯ → БАЛЛЫ», «+100», «*за одобренный материал».
5. Добавь раздел «Полезное уже ждёт в каталоге».
6. Сначала создай структуру одной карточки. Сверь поля со справочником, затем добавь ещё три с другими данными.
7. Добавь «Не нашёл нужное?», пояснение и переход «Создать заявку».
8. Добавь FAQ с пятью вопросами.
9. Добавь в подвал бренд и видимые ссылки десктопного макета.

Для FAQ выбери details/summary. Первый вопрос изначально открыт. Подтверждённый ответ: «За публикацию одобренного материала и за выполненный заказ».

Для остальных вопросов можно временно использовать предложенные учебные ответы:

- «Что я получаю после покупки?» — «После покупки материал появится в разделе „Мои материалы“».
- «Как заказать услугу?» — «Открой каталог услуг, выбери предложение и обсуди условия с исполнителем».
- «Можно ли загружать чужие материалы?» — «Загружай материалы, на распространение которых у тебя есть право».
- «Что делать при проблеме?» — «Открой раздел правил и помощи».

Эти четыре текста предложены для упражнения; в просмотренном закрытом состоянии макета они не показаны. Позже их нужно сверить с реальным поведением проекта.

Кнопку избранного не вкладывай в ссылку на материал. Для основной навигации используй a, для изменения состояния — button. Размер заголовков пока не важен: проверь их смысловую иерархию.

**Проверка:** без CSS читается вся история страницы, нет пустых смысловых блоков и повторяющихся ID.

## 5. Подготовь шрифт, цвета и базовые правила

1. Подключи Manrope выбранным способом. Если используешь локальные файлы, положи их в assets/fonts.
2. Объяви смысловые переменные из справочника в tokens.css. Начни с реально используемых цветов и размеров.
3. В base.css настрой border-box для элементов и псевдоэлементов.
4. Убери стандартный внешний отступ body.
5. Задай базовую гарнитуру, основной цвет и фон страницы.
6. Сделай размеры и отступы заголовков/абзацев предсказуемыми: не оставляй одновременно случайные стандартные margin и промежутки контейнеров.
7. Поля ввода и кнопки позже должны наследовать гарнитуру, иначе браузер может показать другой шрифт.
8. Подготовь общий класс контейнера: максимум 1280 px, центрирование, свободное уменьшение на узком экране.

Подсказки: :root, var, box-sizing, font-family, font-weight, line-height, margin, max-width, margin-inline. Внешние поля при ширине 1440 получаются по 80, но не нужно сохранять по 80 на каждом размере экрана.

**Проверка:** при 1440 px левая граница основного текста соответствует макету; при сужении окна контейнер уменьшается. В Computed действительно указан и отрисовывается Manrope.

## 6. Настрой общую раскладку десктопа

Пока работай на ширине viewport 1440 CSS px при обычном масштабе браузера.

1. Главный поток main сделай Grid в одну колонку смысловых секций.
2. Для него используй верхнее поле 32, нижнее 40 и промежутки 24.
3. Внутри раздела материалов сохрани расстояние 24 между его заголовком и списком; внутри FAQ — 24 между заголовком и вопросами. Это нужно после смыслового объединения элементов в section.
4. Не задавай всей странице высоту 1448: сайт должен расти при открытии FAQ и изменении текста.
5. Пока обозначь фоны крупных блоков, чтобы видеть их границы.

Подсказки: display, grid-template-columns, gap, padding-block. Для высоты текстовых областей предпочитай содержимое и при необходимости min-height.

**Проверка:** main действительно Grid во вкладке Layout. Порядок секций соответствует HTML, внешний край секций общий.

## 7. Собери шапку и общие действия

1. Сделай белый фон шапки на всю ширину, а содержимое — в общем контейнере.
2. Размести бренд слева, действия справа. Здесь подходит Flexbox.
3. Внутри бренда размести экспортированную иконку и текст с промежутком 8.
4. Настрой вертикальные поля шапки 20 и промежуток между крупными группами 24.
5. В components.css опиши общий внешний вид элемента действия: шрифт Label, высота около 48, радиус 12, центрирование содержимого.
6. Добавь вариант Primary: акцентный фон и тёмный текст.
7. Добавь вариант Secondary: белый фон, граница цвета line, тёмный текст.
8. Задай размеры действий шапки из справочника. Оформление остаётся общим, ширина может зависеть от места использования.
9. Добавь различимые hover и focus-visible. Для Primary цвет hover уже есть среди переменных.

Реальную иконку бренда экспортируй из Figma в SVG и положи в assets/icons. Аналогично поступи с сердцами и меню. Пока иконки не экспортированы, оставь это явным незавершённым пунктом визуальной проверки.

Подсказки: display: flex, align-items, gap, flex-grow или автоматический margin. Не выталкивай кнопку вправо большим случайным margin-left.

**Проверка:** шапка близка к 88 px, действия стоят в одном ряду; Tab показывает фокус. Это ссылки на вход/регистрацию, даже если визуально выглядят кнопками.

## 8. Собери приветственный блок

1. Дай внешнему блоку тёмный фон и радиус 16.
2. Добавь padding 32 и расстояние 24 между областями.
3. Сделай внешнюю раскладку Grid: гибкая область текста и область баллов. На ширине макета плашка баллов имеет ширину 310.
4. Внутри текста используй колонку Flexbox с gap 12.
5. Настрой заголовок 32 / 800 и межстрочный 1.4; описание 15 / 400.
6. Плашке баллов дай акцентный фон, padding 24, радиус 16 и внутренний gap 8.
7. Число +100 оформи как Display 44 / 800; это текст, а не изображение.
8. Оформи действие регистрации общим классом Primary.

Подсказки: grid-template-columns, minmax, align-items, flex-direction. Фиксированная ширина текстовой области 850 из Figma не нужна: текст должен получать остаток доступного места.

**Проверка:** на 1440 плашка справа, надписи не обрезаны; при небольшом изменении ширины текст переносится. Не выставляй каждой строке точные x/y из редактора.

## 9. Собери одну карточку, затем сетку четырёх

Сначала работай с одной карточкой, включая длинное название «Алгоритмы и структуры».

1. У article задай фон, padding 16 и радиус 16.
2. Внутри используй Flexbox-колонку, gap 12.
3. Верхнюю строку сделай Flexbox-рядом: тип и курс слева, избранное справа.
4. Для области названия и описания сделай внутреннюю колонку с gap 8.
5. Разреши этой средней области получать свободное место: тогда автор и цена будут внизу без пустых строк.
6. Название — 24 / 28, насыщенность 700; описание — 13 / 18, цвет muted.
7. Сделай тонкий разделитель перед нижней строкой.
8. Нижнюю строку сделай Flexbox-рядом с распределением по краям и центрированием по высоте.
9. Цена получает светлую плашку с радиусом 8, внутренними полями 4 по вертикали и 10 по горизонтали.
10. Используй минимум высоты около 228 для десктопного образца; разреши рост, если содержимое длиннее.
11. После проверки первой карточки добавь остальные на той же структуре и с теми же классами. Различай пастельные фоны модификаторами.
12. Родителю четырёх article задай Grid с четырьмя равными колонками и gap 16.

Подсказки: repeat, minmax(0, 1fr), flex-grow, min-width: 0, justify-content: space-between. Не делай разные размеры текста только ради одинаковой высоты карточек.

**Проверка:** при контейнере 1280 ширина каждой карточки получается 308. Цены находятся на одной нижней линии в строке; длинное название видно целиком; сердце не перекрывает текст.

## 10. Собери блок создания заявки

1. Подготовь светло-зелёный фон, радиус 16 и padding 24.
2. На десктопе используй Grid для текстовой области и действия справа.
3. Внутри текста сделай заголовок 18 / 700 и описание 15 / 400, промежуток 4.
4. Действие оформи Primary; ориентир ширины 260, высоты 48.
5. Высоту блока оставь способной расти: 112 px — размер текущего образца, а не предел для любого текста.

**Проверка:** действие не налезает на описание. У гостя будущий сценарий заявки должен проходить через вход; пока серверной логики нет, не имитируй создание заявки сообщением «успешно».

## 11. Оформи FAQ

1. Между пунктами задай gap 8.
2. Пунктам дай белый фон и радиус 12.
3. В summary размести вопрос и декоративный знак раскрытия; не добавляй внутрь summary отдельную кнопку.
4. Горизонтальные поля — 24. Закрытый пункт ориентируется на минимум 56 px, открытый первый — примерно 80 при текущем тексте.
5. Ответу дай цвет muted и размер 14; вопросу — 16 / 700.
6. Состояние раскрытия оформляй через атрибут open; размер не должен обрезать ответ.
7. Проверь маркер summary: если скрываешь стандартный и рисуешь свой, интерактивный смысл и видимый фокус должны сохраниться.

**Проверка:** первый ответ виден сразу; остальные раскрываются мышью и клавиатурой. Два длинных ответа не накладываются на следующий блок.

## 12. Собери подвал

1. Внешний фон — dark; текст — onDark.
2. На десктопе сохрани бренд слева и навигацию около центра всего контейнера.
3. Для этого подойдёт Grid с симметричными боковыми областями и центральной областью навигации.
4. Поля по вертикали — 32; расстояние между ссылками — 36.
5. Показывай только видимые элементы актуального десктопного макета. В дереве есть скрытые старые группы — их не нужно переносить.

**Проверка:** навигация центрирована относительно всего контейнера, а не только оставшегося места справа от бренда. Подвал находится после FAQ в обычном потоке документа.

## 13. Проверь десктоп перед адаптацией

Сравни страницу со снимком при 1440 CSS px. Сначала проверяй структуру и ширины, затем шрифт, затем расстояния, затем мелкие границы и иконки. Другой шрифт меняет переносы и может создать ложное впечатление неправильной сетки.

Проверь восемь областей: шапка, h1, приветствие, карточки, блок заявки, заголовок FAQ, вопросы, подвал. Не исправляй разницу глобальным масштабированием страницы.

**Контрольная остановка A:** уже можно прислать работу на проверку. Укажи, что готов десктоп и до мобильной части ты ещё не дошёл.

## 14. Добавь планшет через media-запрос

Стартовая учебная граница — ширина до 1199 px. Она предложена для реализации, отдельный планшетный макет не проверен.

1. Уменьши боковые поля общего контейнера до 24–32.
2. Сетку материалов оставь Grid, но сделай две колонки.
3. Проверь приветствие: если две области тесны, перестрой его в одну Grid-колонку; не переключай планшет на Flexbox.
4. Проверь шапку и блок заявки: разреши разумный перенос/рост, не сжимай текст до нечитаемого размера.
5. Проверь 1024 и 768 px. При 768 основная раскладка и материалы всё ещё Grid.

Подсказки: @media, max-width, grid-template-columns, gap, padding-inline. Не копируй в media-запрос весь CSS-файл: переопредели только изменившиеся свойства.

**Проверка:** на планшете два материала в строке, горизонтального скролла документа нет.

## 15. Добавь телефон через media-запрос и Flexbox

Стартовое условие — ширина до 767 px. Мобильный макет даёт эталон на 390 px; поведение между ширинами проверяешь в браузере.

1. Переключи main с Grid на Flexbox-колонку. Его верхнее поле — 24, нижнее — 32, промежутки — 20.
2. Переключи внешний контейнер материалов с Grid на Flexbox-колонку с gap 16. Одной Grid-колонки для этого требования недостаточно: проверь фактический display.
3. Переключи приветственный блок на Flexbox-колонку. Padding — 20 по вертикали и 16 по горизонтали, gap 20. Убери ограничения ширины, мешающие плашке баллов заполнять доступное место.
4. Сделай главный заголовок 32 / 40; заголовок приветствия — 26 / 34.
5. Сделай поля основного контейнера по 16: при 390 ширина контента получается 358.
6. Карточки растягиваются на ширину контейнера. В мобильном образце высота 264; используй подходящую минимальную высоту с возможностью роста.
7. Переключи блок заявки на Flexbox-колонку. Padding 20 / 16, gap 20, действие занимает доступную ширину.
8. В шапке вместо большой ссылки регистрации предусмотрена кнопка меню; вход остаётся видимым. Высота шапки около 64, поля 10 / 16, высота действий 44.
9. Уменьши бренд до мобильного варианта: текст около 20 px. На ширине 320 при необходимости разреши перенос группы действий; это предлагаемое решение для ширины меньше макета.
10. В FAQ разреши перенос длинных вопросов и рост высоты. Не оставляй у summary жёсткую высоту 56, обрезающую второй ряд.
11. Переключи подвал на Flexbox-колонку, padding 24, gap 12; отцентруй бренд и полезные ссылки. Мобильные подписи: «Каталог», «Баллы», «Помощь».
12. Проверь, что не остались ширина 1280, 850, 310 или другие жёсткие размеры, выходящие за доступное место.

Мобильный пункт «Баллы» для упражнения можно связать с вопросом FAQ о получении баллов. Отличающиеся подписи ссылок подвала можно реализовать общим списком с разумной адаптацией; если делаешь отдельные варианты навигации, скрытый вариант не должен оставаться в порядке Tab.

Подсказки: display, flex-direction, align-items: stretch, width, max-width, min-width, gap. Правила grid-column при display: flex не размещают элемент; размеры и margin продолжают действовать.

**Контрольная остановка B:** десктоп → планшет → телефон работают в одном HTML. Ты можешь указать правило, которое реально переключает Grid на Flexbox.

## 16. Добавь поведение после вёрстки

1. Подключи landing.js с defer.
2. Начни с открытия и закрытия мобильного меню. Алгоритм и API есть в [JS-шпаргалке](05-javascript-cheatsheet.md).
3. Для первой версии используй простую раскрывающуюся панель ссылок; она не должна перекрывать элементы непредсказуемым образом.
4. Меняй aria-expanded вместе с видимостью. Проверь Escape и возврат фокуса.
5. FAQ оставь на встроенном поведении details, если дополнительного требования нет.
6. После этого по желанию добавь переключение избранного. Хранение после перезагрузки — ещё один самостоятельный шаг.

**Проверка:** в Console нет ошибок; закрытые пункты меню недоступны Tab; открытие меню не меняет размеры карточек через JS.

## 19. Репетиция защиты: меняй CSS и объясняй

Сначала предскажи эффект словами, потом измени одно правило и проверь. После упражнения верни исходное оформление или сохрани вариант отдельно.

| Задание преподавателя | Где искать изменение | Что объяснить |
|---|---|---|
| Сделай три карточки в строке | grid-template-columns у списка | Что будет с четвёртой карточкой |
| Увеличь промежуток с 16 до 24 | gap у списка | Почему ширины карточек уменьшились |
| Пусть первый элемент занимает две колонки | grid-column у первого ребёнка | Разница свойств контейнера и ребёнка |
| Сделай планшет в одну колонку | Планшетный grid-template-columns | Почему раскладка всё ещё Grid |
| Переключи телефон с колонки в ряд | flex-direction | Как повернулись главная и поперечная оси |
| Разнеси автора и цену по краям | justify-content строки | Чем space-between отличается от gap |
| Выровняй элементы строки по высоте | align-items | По какой оси действует свойство |
| Запрети сжимать иконку | flex-shrink у иконки | Почему правило ставится ребёнку |
| Прижми цену вниз при длинном названии | Рост средней области / auto-margin | Откуда берётся свободное место |
| Измени границу телефона | Условие @media | Какие правила действуют по обе стороны |
| Увеличь padding карточки | padding | Как border-box влияет на внешний размер |
| Измени акцент всех действий | CSS-переменная | Почему не нужно менять каждую кнопку |
| Удали display: grid | Правило внешней сетки | Почему grid-template-columns перестал размещать детей |
| Объясни minmax(0, 1fr) | Размеры колонок | Доли свободного места и минимальный размер трека |
