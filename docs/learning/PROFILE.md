# Профиль работы

Обновлено: 22 октября 2026. Источник — прямые пожелания пользователя в этом чате.

## Цель и формат

Собрать «УниМаркет» по Figma и подготовиться к защите практической. Пользователь предпочитает готовые фрагменты для копирования и помощь ИИ в файлах; предварительно учить весь синтаксис не требуется.

- ИИ предлагает небольшой шаг: результат → точный файл и место вставки → готовый код → короткое объяснение → проверка.
- Пользователь вставляет код сам либо просит ИИ создать, дописать или исправить файлы. Самостоятельное написание кода не является условием продолжения.
- Подход можно обсуждать. Давать понятные варианты и рекомендацию, не требовать уже знать архитектуру и термины.
- Не превращать каждый шаг в экзамен или повторное согласование. Теорию объяснять на текущем коде, подробнее — по запросу.
- Сохранять выполненное, оставшееся, ответственность файлов и связи частей проекта.
- Не считать согласие или чтение объяснения доказательством освоенного навыка.
- Все комментарии в исходниках и конфигурации писать на русском языке; имена файлов, классов и стандартные ключевые слова сохраняют обычное написание.

## Ограничения

- Лендинг предназначен только для гостя. Его карточки — демонстрационные, без ID реальных материалов; названия материалов — обычные заголовки без ссылок. Сердца и каталог ведут на вход. После авторизации пользователь переходит в настоящий каталог, а не в первую демонстрационную карточку; проверку сессии реализовать вместе с авторизацией.
- Корзины в проекте не будет: решение пользователя от 22 октября. Покупка материала — непосредственно со страницы описания.
- Обязательно применять ponytail, KISS и DRY. Код максимально краткий и читаемый, без лишних абстракций и кода на будущее.
- Жёсткого лимита строк нет. Полноценный HTML-файл страницы в 300–400 строк допустим; делить по назначению и удобству чтения, не ради счётчика.
- Пользователь согласовал простую структуру: index.html, pages/ и assets/. HTML-фрагменты и сборка отменены.
- Вход, регистрацию и восстановление доступа объединять в одной странице pages/auth/login.html, а не в отдельных HTML-файлах.
- Шапка должна оставаться компактной. После уточнения пользователя размер 100 × 100 отменён: SVG без пустых полей, логотип 64 × 64 px на ПК/планшете и 48 × 48 px на телефоне; размеры задаёт base.css.
- На мобильном лендинге избегать переносов кнопок шапки и пустой высоты карточек. Вход и регистрация видны обычными кнопками от 600px, ниже — двумя прямыми ссылками с иконками, без меню. До 600px кнопка регистрации в приветствии занимает всю ширину, как плашка баллов. Плашка «+100 баллов» центрирована, без «ЗНАНИЯ → БАЛЛЫ». Карточки компактные, их высоту определяет содержимое.
- У полей ввода и select выделять собственную границу при фокусе, без внешней рамки с отступом. У ссылок и кнопок сохранять видимый клавиатурный фокус.
- Нужна модульная структура и осмысленное ООП для логики; HTML/CSS остаются семантическими документами и стилями.
- HTML, CSS, vanilla JavaScript; backend — PHP и MySQL/MariaDB. Без React/Vue/Angular в текущем объёме.
- Главная: Grid на компьютере и планшете, Flexbox через media-запросы на телефоне.
- На защите нужно менять и объяснять основные правила Grid/Flexbox. Репетируем на созданной странице.
- Сначала десктоп, затем планшет и телефон. По уточнению 22 октября адаптацию проектируем самостоятельно: мобильные страницы Figma не использовать как образец и не перечитывать для реализации.

## Словарь CSS-классов

Согласован 22 октября. Английские слова, которые можно оставлять: actions, author, banner, blue, brand, button, card, container, content, faq, footer, green, grid, header, item, items, landing, link, main, material, materials, meta, nav, points, price, save, secondary, site, skip, welcome.

По уточнению пользователя inner заменяется на vnutri. primary заменяется на main. Остальные слова из первоначального списка переименованы: bottom → niz, top → verh, lavender → lavandoviy, request → zayavka, reward → nagrada.

Новые слова вне согласованного словаря по умолчанию писать понятным транслитом. Сохранять разделители классов __ и --; это соглашение имён, не ограничение синтаксиса HTML. Стандартные теги, атрибуты, CSS-свойства и значения не переводить. IDs и имена ресурсов не переименовывались в этой задаче.
