## Предварительные связи данных

Это концептуальная модель по требованиям, **не утверждённая схема таблиц**:

- Пользователь → публикует материалы/услуги, создаёт заявки, оставляет отклики.
- Материал → автор, учебные характеристики, содержимое для покупателя.
- Покупка → покупатель, материал, доступ в кабинете, история баллов.
- Заявка → заказчик, отклики, выбор исполнителя, дальнейший заказ.
- Заказ → участники, обсуждение, состояние, результат, допустимый отзыв.
- Модерация → решение о публикации и доступность в каталоге.

HTML/CSS показывают данные, JS обеспечивает взаимодействие, PHP подтверждает права и операции, база хранит результат. Конкретные API, поля, таблицы и серверные маршруты ещё неизвестны.

## Актуализация

После законченного изменения: проверить реальные файлы и результат → обновить пункт PROGRESS → поправить пути и связи здесь. PROFILE менять при изменении предпочтений, а не после каждой правки CSS.

Непроведённую проверку отмечать прямо. Не сохранять секреты, полный текст чата или выдуманные команды запуска. Не проводить повторный полный аудит макетов после каждой небольшой правки.
