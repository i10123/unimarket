# Как устроена страница входа

Редактируем pages/auth/login.html. Все три формы лежат здесь; оформление — assets/css/auth.css, поведение — assets/js/auth.js. Сначала подключается общий base.css, затем стили страницы. Путь ../../assets/ поднимается на два уровня от pages/auth/ к корню проекта.

## Переключение форм

Ссылка #registraciya выбирает регистрацию. auth.js читает эту часть адреса и задаёт атрибут data-ekran="registraciya" у html. CSS-правило [data-ekran="registraciya"] #registraciya показывает нужную секцию; остальные скрыты. При смене адреса событие hashchange обновляет атрибут и возвращает страницу вверх. Кнопки браузера «Назад/Вперёд» тоже поддерживаются.

Скрипт подключён в head без defer: режим выбирается до разбора содержимого body и первой отрисовки формы. Это устраняет краткий показ входа при прямом открытии регистрации. Обработчики полей устанавливаются внутри DOMContentLoaded, когда HTML уже существует. Без JavaScript доступен только макет входа с отключённой отправкой и пояснением.

display: none убирает неактивные формы из раскладки, клавиатурного обхода и дерева доступности. Одного opacity: 0 недостаточно: прозрачные поля продолжили бы занимать место и получать фокус.

## Ширина и отступы

Общее правило html { scrollbar-gutter: stable; } резервирует место под вертикальную полосу прокрутки. Без него длинная регистрация и лендинг сужают доступную ширину, а короткий вход расширяет её: центрированный контейнер и логотип заметно сдвигаются. Правило сохраняет одинаковую доступную ширину страниц.

width: min(520px, 100%) ограничивает форму шириной из десктопного макета и позволяет ей сжиматься на телефоне. У main align-items: center центрирует форму по горизонтали. Внутри формы flex-direction: column располагает заголовок, поля и кнопки сверху вниз, gap: 16px задаёт расстояния между ними.

padding — внутреннее расстояние от края карточки до содержимого; gap — расстояние между её дочерними элементами. Эти свойства решают разные задачи. В мобильном media-запросе уменьшаются внутренние отступы и заголовок. Поля получают шрифт 16px, чтобы мобильный браузер не увеличивал страницу при вводе.

## Поля и кнопки

label связан с input через for/id: нажатие на подпись переводит фокус в поле, экранный диктор получает понятное имя. required требует заполнить поле, type="email" проверяет формат, minlength="8" ограничивает длину нового пароля. autocomplete подсказывает браузеру назначение поля. Повтор пароля сравнивается с основным в JS через setCustomValidity.

При неудачной отправке событие invalid добавляет форме класс dostup__forma--proverena. CSS выделяет все её :invalid поля красной границей, а не только первое. До попытки отправки класс отсутствует, поэтому пустая форма не выглядит ошибочной. После исправления браузер перестаёт считать поле :invalid, и его обычная граница возвращается сама. Событие invalid не всплывает: true в addEventListener включает захват событий дочерних полей.

preventDefault на invalid убирает всплывающую подсказку браузера, но не отключает проверку полей и блокировку отправки невалидной формы. Вместо подсказки функция obnovitOshibki выводит общий текст под кнопкой, отмечает поля aria-invalid и обновляет сообщение по мере исправления. Сначала она сообщает о незаполненных полях, затем о неверном email, паролях или согласии. Когда все ошибки исправлены, сообщение скрывается. role="status" позволяет экранному диктору объявить изменившийся текст.

У кнопки с глазом type="button", поэтому она не отправляет форму. Она меняет type поля между password и text, а aria-pressed сообщает её состояние. Кнопка действия имеет type="submit"; браузер проверяет поля, после чего обработчик submit отменяет отправку и показывает пояснение. Данные не уходят в URL, localStorage или на сервер.

В HTML кнопки отправки изначально disabled. JS включает их после установки обработчика: без скрипта случайная отправка формы остаётся недоступной.

## Оформление списка курсов

В auth.css блок @supports (appearance: base-select) включает оформление самого select и его ::picker(select). Пункты option подсвечиваются при :hover/:focus, выбранный вариант имеет :checked и встроенную отметку ::checkmark. Вся логика выбора, Escape, стрелки, отправляемое значение и required остаются у браузера. Это позволяет обойтись без отдельного JS-компонента. В браузере без поддержки блок пропускается и сохраняется системный список; [описание и ограничения на MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select).

Проверка: открой список, выбери курс стрелкой вниз и Enter; повторное раскрытие покажет галочку. Escape закрывает меню без нового выбора. Эти проверки выполнены ИИ в браузере, выполнение пользователем пока не проверялось.

## Что ещё не реализовано

Это интерфейс и локальные проверки, а не настоящая авторизация. Email существующего пользователя, хэш пароля, сессию и права должен проверять PHP. Браузерные ограничения можно обойти, поэтому сервер обязан повторить проверки. Подтверждение кода, новый пароль и результат сброса добавим при подключении соответствующего сценария; письмо сейчас не отправляется.

## Мини-практика

1. Открой на лендинге «Создать аккаунт»: адрес заканчивается на #registraciya, видна только регистрация.
2. В auth.css временно измени 520px на 600px. На компьютере форма станет шире, на узком телефоне останется ограниченной контейнером. Верни 520px.
3. Измени gap формы с 16px на 24px и сравни с изменением padding. Верни исходные значения.
4. Введи разные пароли и попробуй создать аккаунт. Исправь повтор пароля: ошибка должна исчезнуть. Заполненная форма покажет, что сервер ещё не подключён.
5. Переключись между лендингом, входом и регистрацией: логотип должен оставаться на одной горизонтальной позиции. В инструментах разработчика временно отключи scrollbar-gutter и сравни результат, затем включи обратно.

Выполнение этих упражнений пользователем пока не проверялось.
